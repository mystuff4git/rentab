# ADR 0006. Фаза 4: приватность, файл профиля JSON, несколько проектов

- Статус: принято
- Дата: 2026-10-22
- Фаза: 4

## Контекст

v0.3 писал профиль фирмы (оклады, ставки) в `data/firm_profile.json` на диске
сервера и загружал его в каждую новую сессию (L-10). На Streamlit Community
Cloud это один файл на всех посетителей. Профиль хранил модель цены русской
подписью, а маржу — целыми процентами (L-16).

С фазы 1 приложение на диск не пишет: данные живут в `st.session_state`, а
при закрытии вкладки пропадают. Фаза 4 даёт пользователю сохранить работу
так, чтобы сервер ничего не хранил, добавляет демо-фирму и несколько проектов в
сессии и закрепляет отсутствие записи тестами.

Решения согласованы с автором до реализации:

- пошлины хранятся в файле как выбор, а не как суммы;
- плоская ставка взносов v0.3 по умолчанию пересчитывается при импорте;
- демо — пять проектов;
- дисклеймер: «данные не покидают вашу сессию», а не «ваш браузер».

## Решение

### Файл профиля (`rentab_core.io`)

- Конверт: `format: "rentab"`, `schema_version: 1`, справочно `exported_at` и
  `app_version`. Содержимое — `Workspace`: фирма, последние загруженные курсы
  (`rates_quote`: источник и дата) и проекты.
- Фирма и проект — модели ядра (`Firm`, `Project`) как есть, поэтому файл
  покрывает всё, что знает расчёт: утилизацию, оклад или сумму в месяц,
  «из прибыли», тариф взносов, `FirmFacts`, режим НДС, модели цены.
- `ProjectRecord` = `Project` + выбор пошлин по странам (`DutySelection`:
  действия, количества, категория заявителя). В `project.disbursements` —
  только расходы, введённые вручную. Пошлины пересчитываются по актуальному
  каталогу при расчёте: суммы Роспатента и Казпатента ещё сверяются
  (`needs_review`), и исправленный каталог должен доходить до старых проектов.
  Суммы на дату выгрузки пишутся справочно (`amounts_at_export`); если
  каталог изменился, импорт об этом сообщает. Пошлину, которую нужно
  «заморозить» (например, для отправленного КП), вводят как произвольный
  возмещаемый расход.
- Суммы — строками Decimal; при чтении числа JSON переводятся в Decimal,
  минуя float. `NaN` и `Infinity` отклоняются, файл больше 2 МБ — тоже.
- Ядро на диск не пишет: `dumps` возвращает байты для кнопки «Скачать»,
  `loads` читает байты загруженного файла. Ошибки — `ProfileImportError` с
  путём к полю по-русски, замечания — `ImportNote` двух уровней.
- Версии: шаг миграции переводит словарь JSON версии N в N + 1
  (`io.migrations.MIGRATIONS`) и не зависит от моделей. JSON Schema формата —
  `docs/profile.schema.json`; тест сравнивает её с моделями, так что изменение
  моделей нельзя не заметить: либо новая версия и шаг миграции, либо
  осознанное обновление схемы.

### Импорт профиля v0.3 (L-16)

Профиль v0.3 — чужой формат, а не версия 0 этого: его переводит в текущие
модели отдельный импортёр `io/v03.py`. Это единственное место ядра, которое
знает формат v0.3; characterization-адаптер переводит сценарии v0.3 сам.
Правила — как `FINAL` в ADR 0004:

- себестоимость часа v0.3 — стоимость контрактного часа, утилизация 65%;
- если `cost_rate` совпадает с калькулятором ФОТ v0.3 (до копейки в час),
  сотрудник переносится с окладом — так работает уменьшение налога УСН на
  взносы; иначе — суммой в месяц `cost_rate × часы`;
- ставка взносов, равная умолчанию v0.3 для режима (30%, 0%, 11,5% в РК),
  пересчитывается по реестру 2026 года; заданная вручную остаётся;
- биллируемые часы фирмы не переносятся (ёмкость считается по команде);
- модель цены и целевая маржа становятся настройками пустого проекта: в
  профиле v0.3 проектов не было, а «настройки проекта по умолчанию» — лишнее
  понятие.

Каждое изменение объясняется замечанием импорта.

### Несколько проектов в сессии

- Активный проект живёт в прежних ключах виджетов, неактивные — в слотах
  (`ProjectSlot`) снимками этих ключей вместе с последней сметой.
  Переключение, новый проект, копия и удаление — колбэки в боковой панели.
- При загрузке проекта каждый ключ его виджетов задаётся явно, в том числе
  выбор пошлин, слайдер маржи, потолок и страна расчёта. Браузер хранит
  значение виджета, который остаётся на экране, и не заменяет его новым
  `default`; удаление ключа этого не исправляет. AppTest этого не видит:
  ошибку нашёл прогон в браузере (пошлины выпадали из сметы после
  переключения). Сценарий скриншотов это проверяет.
- Сборка моделей — чистые функции от словаря значений (`project_values` ↔
  `project_record`, `firm_values` ↔ `firm`): путь «запись → значения →
  запись» проверяется без Streamlit.
- Целевая маржа в интерфейсе — целые проценты: дробная маржа из файла
  округляется «половина вверх», импорт об этом сообщает.
- Черновик без потолка или согласованной цены выгружается как почасовой,
  интерфейс предупреждает.

### Демо-фирма (`rentab_core.demo`)

Фирма раздела 10.1 `methodology.md` (слайд 3) с суммой в месяц вместо
оклада, чтобы цифры слайда не поменяло уменьшение УСН на взносы. Доход за
год 24 млн ₽ — НДС 5% обязателен, валидатор не возражает. Проекты: слайд 3
по плану и по факту, товарный знак (пример 1 методологии, пошлины за три
класса), изобретение (фикс 30%), ответ на уведомление (потолок 60 000 ₽).

### Приватность

- Дисклеймер на главной: данные — в памяти сессии на сервере; на диск ничего
  не пишется; сохранить работу — скачать JSON. «Не покидают ваш браузер» было
  бы неправдой: Streamlit считает на сервере.
- `.streamlit/config.toml`: `browser.gatherUsageStats = false`,
  `server.maxUploadSize = 2`.
- `tests/app/test_privacy.py`:
  - аудит-хук Python (`sys.addaudithook`) регистрирует открытие файлов на
    запись и операции с файловой системой на полном пути пользователя (демо,
    курсы с кэшем в памяти, сотрудник, проекты, смета, XLSX, выгрузка и
    загрузка JSON, импорт v0.3). Тест падает при записи вне временного
    каталога и при оставленных во временном каталоге файлах;
  - запись во временный каталог разрешена: её делает openpyxl, собирая XLSX
    в памяти, и сразу удаляет файлы;
  - контрольные тесты: регистратор ловит запись и в обычном коде, и в
    скрипте Streamlit;
  - профиль v0.3 в рабочем каталоге и в `data/` не читается;
  - AST-проверка: в `app/` и `rentab_core` нет вызовов записи файлов (кроме
    генераторов документации `main`).
- Разовая проверка настоящего сервера (`streamlit run` с тем же хуком через
  `sitecustomize`, сценарий в браузере): запись только во временный каталог,
  все файлы удалены.

## Последствия

- Цифры смет не меняются: снимки ядра и мост «было/стало» не тронуты.
- Фаза 5 добавит к `ProjectRecord` фактические часы (план–факт) — поле с
  умолчанием; если старые файлы будут читаться без изменений, схема
  обновляется без новой версии.
- Фаза 7 (КП) может хранить в записи проекта условия предложения тем же
  способом.
- Редактирования сотрудника в интерфейсе по-прежнему нет: после импорта
  утилизацию меняют удалением и повторным добавлением. Это фаза 6.
