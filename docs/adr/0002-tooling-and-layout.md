# ADR 0002. Тулинг и структура репозитория

- Статус: принято
- Дата: 2026-10-21
- Фаза: 0

## Контекст

Ядро должно быть чистым Python-пакетом, пригодным для API или другого фронта,
а UI — тонким слоем на Streamlit. Проект открытый и портфолийный: важны
воспроизводимость, строгая типизация и понятный CI.

## Решение

- **Менеджер окружений — uv**, зависимости фиксируются в `uv.lock`; CI ставит их
  через `uv sync --locked`.
- **src-layout**: пакет `rentab_core` в `src/`, сборка через hatchling, версия
  берётся из `rentab_core.__version__`. Дистрибутив называется `rentab`.
- **Группы зависимостей**: `dev` (pytest, pytest-cov, hypothesis, ruff, mypy) и
  `legacy` (pandas, openpyxl для тестов v0.3). Обе ставятся по умолчанию.
- **Граница ядра**: импорт streamlit и plotly запрещён правилом ruff `TID251`
  везде, кроме `app/`. Плюс тест, который в чистом процессе проверяет, что импорт
  `rentab_core` не тянет UI-модули транзитивно.
- **ruff**: правила E, W, F, I, B, UP, SIM, C4, N, PT, TID, RUF. RUF001–003
  отключены: на русском тексте они срабатывают на каждой кириллической букве,
  похожей на латинскую.
- **mypy strict** для `src/` и `tests/`. Модули v0.3 (`modules.*`) не
  типизированы и исключены через override.
- **pytest**: `--strict-markers`, `--strict-config`, предупреждения — ошибки,
  coverage ядра с порогом 90% с первого дня. Hypothesis работает в
  детерминированном профиле, чтобы CI и локальные прогоны совпадали.
- **CI**: GitHub Actions, Python 3.11 и 3.13. setup-uv закреплён по SHA коммита:
  у него нет плавающего мажорного тега.

## Последствия

- Нарушение границы ядра ловится линтером ещё до тестов.
- Добавить зависимость = `uv add` + обновлённый `uv.lock` в том же PR.
- При запуске части тестов срабатывает порог покрытия; для быстрых прогонов —
  `pytest --no-cov`.
