# ADR 0009. Фаза 7: КП в DOCX и PDF, смета XLSX с живыми формулами

- Статус: принято
- Дата: 2026-10-25
- Фаза: 7

## Контекст

До фазы 7 у приложения был один документ — смета XLSX в оформлении v0.3:
числа без формул, НДС и возмещаемые расходы отдельными строками, цены этапов
фикса по теневой стоимости (L-17, цифры — с фазы 2). Коммерческого
предложения для клиента не было; название фирмы вводилось на шаге
«Результат», реквизитов и логотипа не было вовсе.

Решения согласованы с автором до реализации — по рекомендациям, с одной
правкой: в КП без НДС пишется «Без НДС», без ссылки на НК РФ.

## Решение

### КП: содержимое (`export/offer.py`)

- Одна модель документа `OfferDocument` по смете — для DOCX и PDF. Модель
  знает, что написано и какие суммы; оформление — у рендереров.
- Разделы:
  - шапка — логотип, название, реквизиты, адрес, контакты;
  - «Коммерческое предложение № … от …», заказчик, проект, строка «Цена»
    (модель цены и как начисляется НДС);
  - «Задача» — описание проекта;
  - «Состав работ и стоимость»: фикс — этапы с описанием результата и ценой
    по теневой стоимости (L-17); почасовая и с потолком — этапы с
    исполнителями «Имя (роль)», часами, ставкой и суммой без НДС;
  - итог: услуги без НДС, НДС или «Без НДС», услуги с НДС, возмещаемые
    расходы по позициям, «Итого к оплате»; у потолка — «Стоимость по ставкам»
    и «Скидка до предельной стоимости»;
  - «Условия»: фраза модели цены, пошлины «оплачиваются по суммам,
    действующим на дату оплаты, и в стоимость услуг не входят», порядок
    оплаты, срок выполнения, дополнительные условия, «действительно до …»;
  - подпись и банковские реквизиты (если заданы).
- Суммы КП — **до копейки** (`methodology.md`, раздел 20.1). Строки итога —
  значения сметы, округлённые «половина вверх»; «Итого к оплате» — сумма
  строк. Цены этапов и строк исполнителей делятся функцией `allocate`:
  каждая часть округляется вниз, недостающие копейки — частям с наибольшим
  остатком, сумма частей равна итогу ровно. Тесты: демо-проекты, случайные
  сценарии (hypothesis), property-тест `allocate`.

### PDF (`export/pdf.py`) — reportlab

- reportlab 5 — чистый Python, лицензия BSD, зависимости (pillow,
  charset-normalizer) уже были в `uv.lock`. Альтернатива fpdf2 даёт файлы
  меньше, но LGPL-3.0 и ещё два пакета.
- Оформление «классический бланк» (вариант A из двух макетов): белый лист A4,
  бордовая линия под шапкой, заголовки PT Serif, текст и таблицы PT Sans,
  шапка таблицы и «Итого к оплате» на пергаменте. Колонтитул «… · стр. N из
  M»: документ собирается дважды (первый проход считает страницы), это
  десятки миллисекунд.
- Шрифты — TTF PT Sans (обычный и полужирный) и PT Serif Bold из google/fonts
  (OFL, та же гарнитура, что `app/static`) лежат в `rentab_core/export/fonts`
  и встраиваются подмножеством. Тест проверяет, что у каждого шрифта PDF есть
  файл шрифта и ссылок на системные шрифты (Helvetica) нет.
- Вывод детерминирован (`invariant`): одинаковые данные — одинаковый файл.
- Пользовательский текст экранируется: разметка reportlab в нём не работает.

### DOCX (`export/docx.py`) — python-docx

- Документ собирается кодом, без бинарного шаблона; содержимое и оформление —
  как у PDF; номера страниц — поля Word `PAGE` и `NUMPAGES`.
- Шрифты PT Sans и PT Serif **встроены** так, как это делает Word:
  `word/fonts/*.odttf`, первые 32 байта шрифта закрыты ключом из
  `fontTable.xml` (ECMA-376, ч. 1, 17.8.1), `w:embedTrueTypeFonts` в
  `settings.xml` (на своём месте по схеме). Ключи — детерминированные (uuid5).
  Проверено: LibreOffice в окружении без шрифтов ParaType рисует КП
  встроенными шрифтами (тест в `test_xlsx_formulas.py`). Цена — файл ≈ 0,7 МБ.
- Ширины столбцов — и в сетке таблицы, и в ячейках, макет таблицы
  фиксированный: Word читает одно, LibreOffice — другое.
- Время записей архива — дата документа (`style.stable_zip`): одинаковые
  данные — одинаковый файл.

### Смета XLSX с живыми формулами (`export/xlsx.py`)

- Три листа: «Смета» (для клиента), «Внутренний расчёт», «Исходные данные»
  (новый). Раскладка первых двух — прежняя.
- «Исходные данные» — входы в валюте проекта: параметры режима и цены,
  команда фирмы (оклад или сумма, ставка взносов, курс к валюте проекта, H,
  u, ставка для клиента, «из прибыли», учитываются ли взносы), накладные,
  назначения, расходы. Вычисляемые столбцы: `W`, `K = H·u`, `c = W·курс/K`,
  `ĉ`, `s`, `ρ`. Вся команда фирмы — потому что `ρ` делится на ёмкость всей
  команды. Входы — синим шрифтом, формулы — чёрным.
- «Внутренний расчёт»: каждое число — формула (`methodology.md`,
  раздел 20.2): `R` по модели цены (у «издержки + маржа» — закрытая формула
  раздела 7.3 через `MAX`), налог по базе, NNE, маржа, рычаг (`SUMIF` по
  старшим и младшим), этапы — доля по теневой стоимости с запасными ключами,
  собственные расходы этапа, налог этапа по трём ветвям раздела 8.4 (ветвь
  считает блок «Расчёт налога» внизу листа), статус с точностью 10⁻⁶ и цвет
  строки условным форматированием. Справа от таблицы этапов —
  столбцы-помощники.
- «Смета»: формулами — сумма строки, итоги, скидка до потолка, НДС, итог
  возмещаемых и «Итого к оплате»; ссылок на другие листы нет, поэтому
  внутренние листы можно удалить перед отправкой клиенту. Цены этапов фикса —
  числа.
- Только `SUM`, `SUMIF`, `SUMIFS`, `MIN`, `MAX`, `IF`, `AND`, `NOT`, `ROUND`;
  `fullCalcOnLoad`: Excel и LibreOffice считают формулы при открытии.
- Запись — `ExcelWriter` без подмены времени «изменён» и `stable_zip`:
  вывод детерминирован.
- `estimate_xlsx(estimate, *, scenario, ...)`: лист данных нужен фирме, а в
  смете её нет. Новый параметр `validity_days` — срок из условий КП.

### Проверка формул: пересчёт в LibreOffice

- `tests/core/test_xlsx_formulas.py` собирает сметы для сценариев снимков
  ядра (6 именованных + 26 ячеек матрицы), примеров методологии (14), демо (4)
  и 40 случайных сценариев — 90 смет (режимы РФ и РК, оклады и суммы, валюты, все модели
  цены, «включая НДС», привязанные расходы), пересчитывает их одной командой
  `soffice --headless --convert-to xlsx` (≈ 20 с) и сверяет каждую формулу с
  ядром: деньги — до половины копейки (фактически ~10⁻⁸ ₽), доли — до 10⁻⁹,
  статусы — совпадение. Отдельно: формулы проходят все ветви (модели цены,
  базы налога, три ветви налога этапов), ошибок формул нет, «Смета» не
  ссылается на внутренние листы.
- Без LibreOffice модуль пропускается; в CI ставится
  `libreoffice-calc-nogui` и `libreoffice-writer-nogui` в ячейке Python 3.13,
  и там пропуск — ошибка (`RENTAB_REQUIRE_LIBREOFFICE=1`).
- Собственный вычислитель формул не пишется: настоящий движок проверяет
  точнее.

### Снимки XLSX

- `snapshots/core/export/*.json` изменились **только по форме**: 149 чисел
  стали текстом формул; проценты и рычаг были округлёнными числами (31,9;
  1,83), стали формулами, значение которых — доля с форматом «0,0%» (ушло
  ограничение «округление на точной середине»). Добавлены лист «Исходные
  данные», столбцы-помощники этапов и блок «Расчёт налога».
- Каждая изменённая ячейка проверена: значение формулы после пересчёта в
  LibreOffice равно прежнему числу снимка. Тексты и позиции прежних строк не
  изменились. Снимки v0.3 (`snapshots/export`), снимки сметы ядра и мост
  «было/стало» не тронуты.

### Данные: реквизиты, логотип, условия КП

- Поля с умолчанием **без новой версии схемы**, как `actuals`:
  - `letterhead` (верхний уровень файла, `Workspace.letterhead`) —
    реквизиты одной строкой (ИНН/КПП/ОГРН или БИН — подходит и для РФ, и для
    РК), адрес, телефон, e-mail, сайт, подписант, банковские реквизиты,
    логотип; название фирмы осталось `Firm.name`;
  - `projects[].offer` (`ProjectRecord.offer`, место из ADR 0006) — номер,
    срок действия (по умолчанию 30 дней), порядок оплаты, срок выполнения,
    дополнительные условия;
  - `projects[].project.stages[].description` (`Stage.description`) — что
    получает клиент на этапе; в расчёт не входит.
- Пустые поля не пишутся: файл без КП читает и приложение фаз 4–6, файл с КП
  оно отклонит как «неизвестное поле». Это не входы расчёта: `Scenario` их не
  несёт (кроме описания этапа в модели этапа).
- Логотип — base64 в JSON: PNG или JPEG, до 500 КБ (≈ 670 КБ в base64 при
  пределе файла 2 МБ), до 4000 px по стороне. Модель проверяет сигнатуру и
  размер; `documents.read_logo` открывает картинку Pillow, а «бомба
  распаковки» отклоняется как слишком большой логотип. Повреждённый логотип
  при загрузке файла пропускается с предупреждением, остальной бланк остаётся.

### Подписи и формат чисел — в ядре

- `rentab_core.formatting`: «1 234 567 ₽», «40 669,93 ₽» (шаг `KOPECK`),
  проценты, часы, склонение «день/дня/дней»; `rentab_core.labels.regime_label`
  — подпись режима по профилю (L-18). `ui.labels` пользуется теми же
  функциями (реэкспорт), поэтому интерфейс, КП и смета пишут числа одинаково.
- `Estimate.regime_label` остался как в v0.3 — он в снимках ядра и в мосте.

### Интерфейс

- «Фирма» → вкладка «Реквизиты и логотип»: название фирмы (переехало с
  «Результата»), реквизиты, контакты, подписант, банковские реквизиты,
  логотип. Логотип проверяет ядро; после удаления загрузчик получает новый
  ключ (номер растёт), иначе браузер держит прежний файл. Превью — на белом
  листе: в тёмной теме тёмный текст прозрачного PNG иначе не виден.
- «Проект» → «Условия КП» (ключи проекта: снимок в слоте, при загрузке
  задаются явно) и поле «Описание для КП» у каждого этапа. Ключ поля описания
  — проект и **название** этапа: после удаления этапа номера сдвигаются, а
  браузер хранит значение у прежнего ключа; значение пишется в модель этапа
  колбэком.
- «Результат» → «Документы»: «КП (PDF)», «КП (DOCX)», «Смета (XLSX)». Файлы
  собираются **по нажатию** (`st.download_button(data=функция)`,
  `on_click="ignore"`): на каждом перезапуске страница не тратит ≈ 0,2 с на
  три документа. Ядро возвращает байты, Streamlit отдаёт их из памяти. Имя
  файла — без пробелов и знаков, запрещённых в Windows.
- Подсказка «в шапке КП не хватает названия или реквизитов» со ссылкой на шаг.
- Демо-фирма: бланк с заведомо вымышленными реквизитами (нули,
  example.com), логотип `demo_logo.png` (нарисован шрифтами ParaType), условия
  КП и описания этапов у типовых проектов; описания проектов —
  формулировками для клиента. Цифры смет те же.

### Приватность

- Ядро и рендереры пишут только в `io.BytesIO`; AST-проверка (`open`,
  `write_text` и т. п.) проходит.
- Тест приватности: реквизиты, загрузка логотипа (в том числе отказ для
  не-картинки), удаление и повторная загрузка, условия КП, описание этапа и
  скачивание всех трёх документов. Фикстура `downloads` собирает файлы,
  которые Streamlit собирает по нажатию (`MediaFileManager.add_deferred`),
  сразу — как сервер по запросу браузера.
- Разовая проверка настоящего сервера: `streamlit run` с аудит-хуком записи
  через `sitecustomize` и сценарий `docs/screenshots/phase-7/shots.js`
  (загрузка логотипа через браузер, скачивание PDF, DOCX и XLSX): 9 записей —
  все во временном каталоге (openpyxl), вне его — ни одной, оставшихся файлов
  нет.

### Чистое окружение

- Свежий venv на Python 3.11 от uv (python-build-standalone) строго по
  `uv.lock` без dev-групп, установленное колесо Rentab, пустой `HOME`,
  `FONTCONFIG_FILE=/nonexistent`, `python -I`: PDF, DOCX и XLSX собираются,
  в PDF — три встроенных шрифта PT, файлы побайтно совпадают с
  `docs/examples/`.
- Бинарные колёса (Pillow, lxml) несут свои библиотеки; снаружи — только
  glibc и zlib, которые есть в любом образе Debian. `packages.txt` для
  Streamlit Cloud не нужен; сам деплой — фаза 8.

### Найдено и исправлено: L-23

Цена «издержки + маржа» на базе «доходы» при κ = 0 (АУСН, НПД) вычитала
взносы на часах проекта, хотя налог на них не уменьшается: у сотрудника с
окладом и ставкой взносов, оставшейся после смены режима, маржа получалась
ниже цели (11,4% вместо 30%). Ядро теперь считает по формуле раздела 7.3
методологии; снимки ядра и мост не изменились. Нашлось, когда формула
переписывалась в формулу Excel.

## Последствия

- Цифры смет не изменились (кроме L-23 вне снимков): снимки ядра, мост
  «было/стало» и golden-тесты прошли без `--update-snapshots`; снимки XLSX —
  только по форме.
- Зависимости ядра: reportlab, python-docx (lxml), pillow; dev — pypdf,
  types-reportlab. Шрифты в колесе — ≈ 1,25 МБ.
- В смете XLSX без НДС по-прежнему «НДС не облагается.»: текст входит в
  снимки, а фаза меняет их только по форме. В КП — «Без НДС». Привести смету
  к «Без НДС» — отдельным осознанным обновлением снимков.
- Значения формул XLSX появляются только в программах с движком формул
  (Excel, LibreOffice, Google Таблицы); просмотрщики без него (превью GitHub,
  часть мобильных) покажут пустые ячейки.
- Google Docs не читает встроенные в DOCX шрифты и подставляет свои.
- Дата КП — день скачивания; в файл профиля она не входит.
- Реквизиты — свободной строкой, без проверки ИНН, КПП и БИН.
- Примеры — `docs/examples/` (генератор `tests/export_examples.py`, тест
  актуальности `tests/core/test_examples.py`); скриншоты и браузерная
  проверка — `docs/screenshots/phase-7/`.
