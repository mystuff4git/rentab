# ADR 0007. Фаза 5: аналитика — чувствительность, план–факт, сравнение

- Статус: принято
- Дата: 2026-10-22
- Фаза: 5

## Контекст

Фаза 5 добавляет к смете три инструмента: запас часов до безубыточности,
торнадо и «что если» (чувствительность), план–факт и матрицу «модель цены ×
налоговый режим». Формулы — `methodology.md`, разделы 16–19 (написаны и
согласованы с автором до кода). Цифры существующих смет не должны меняться.

Решения согласованы с автором до реализации.

## Решение

### Методологические решения

- **Фикс «издержки + маржа» в чувствительности и план–факте: цена держится.**
  Цена считается по плану — это уже предложение клиенту. Если бы она
  пересчитывалась, `NNE = m*·P` росло бы вместе с часами и точки
  безубыточности не было бы. Пересчитанная цена показывается справочно в «что
  если».
- **Запас часов — закрытой формулой.** NNE при `x` дополнительных часах —
  минимум линий `α − β·x` (ветви налога «доходы» с уменьшением на взносы и
  пределом κ, «доходы − расходы» с минимальным налогом и вознаграждением из
  прибыли; части выручки с потолком). Точка — `min(α/β)` по линиям с `β > 0`.
  Почасовая модель: точка «не наступает», если час окупает себестоимость с
  накладными и налогом; дополнительно — вариант «часы сверх плана не
  выставляются». Микс — пропорциональный рост всех назначений; «роль» —
  каждый сотрудник команды отдельно (в одной роли себестоимость часа разная).
- **Почасовая модель в план–факте: выставляется факт** (часы × ставки), с
  потолком — не больше потолка. Плюс поле «выставлено вручную» для любой
  модели: уступка по часам и скидка с фикса.
- **Реализация выше 100%** показывается как есть («премия к ставкам»);
  списание и премия — отдельные неотрицательные строки; без ставок — «—».
- **Работа вне плана** — строка факта «этап × сотрудник» на существующем
  этапе с планом 0; перерасход — все её часы, процента нет. Пара плана без
  строки факта — 0 ч с предупреждением.
- **Матрица сравнения**: по умолчанию строка на режим (вариант НДС фирмы или
  первый без блокирующих замечаний), «все варианты» — по строке на каждый;
  строки — только стран юрисдикции; в «Оба» — две группы (страна строки
  становится страной расчёта), суммы другой страны дополнительно в валюте
  проекта. Недоступные режимы помечены причинами `check_profile`, их сметы
  считаются и показываются приглушённо.
- **Взносы при сравнении режимов**: ставка сотрудника с окладом, совпадающая
  с расчётной для текущего режима (до 0,01 п. п.), пересчитывается по режиму
  строки (АУСН — 0%); ручная ставка остаётся. Строка текущего режима равна
  смете проекта.

### Модель данных и файл

- `ActualHours` (этап, сотрудник, часы) и `ProjectActuals` (часы, `billed`) в
  `models.py`; `Project.actuals: ProjectActuals | None`. Проверка: этап факта
  существует, пары уникальны. Смету плана факт не меняет. ADR 0006
  предполагал поле в `ProjectRecord`; факт положен в `Project`, чтобы
  `Scenario` оставался полным входом расчёта (план–факт — функция от него), а
  этап факта проверялся тем же валидатором, что и этап расхода.
- `calculate_estimate(..., revenue=...)`: выручка без НДС, заданная извне
  (цена, которая держится, или выставленная сумма). По умолчанию `None` —
  поведение прежнее, поэтому снимки ядра и мост «было/стало» не тронуты.
- Файл профиля: новое поле `projects[].project.actuals`, **версия схемы
  остаётся 1** — старые файлы читаются без изменений (фикстура выгрузки фазы 4
  `tests/fixtures/profile/phase4_demo.json` и тест: замечаний нет, сметы
  прежние, повторная выгрузка совпадает байт в байт). Проект без факта
  выгружается без поля — такой файл читает и приложение фазы 4; файл с фактом
  оно отклонит как «неизвестное поле». Миграция не нужна.
- «Что если», отклонение торнадо и потолок для сравнения — состояние сессии
  (у каждого проекта своё), в файл не попадают: это инструменты, а не данные
  проекта.

### Ядро

- `analysis/sensitivity.py`: `break_even`, `tornado`, `what_if`,
  `apply_what_if` (проект не меняется — строится изменённая копия сценария).
  Курс — цена валюты в валюте проекта: множитель на `rub_per(F)`, а для рубля
  в проекте в тенге — делитель на все остальные курсы.
- `analysis/plan_fact.py`: смета по факту, реализация, перерасход по парам,
  этапам (без собственных расходов), сотрудникам и ролям.
- `analysis/compare.py`: строки, столбцы, ячейки с текстом ошибки (цель
  недостижима, нет курса, не задан потолок), лучшие ячейки.
- Property-тесты сверяют закрытую формулу запаса часов с полным пересчётом
  сметы на случайных фирмах (оклады и суммы, «из прибыли»), режимах РФ и РК и
  моделях цены; тождества перерасхода; «факт = план ничего не меняет»;
  текущая ячейка матрицы = смета проекта.

### Интерфейс

- Страницы «04 Чувствительность», «05 Сравнение», «06 План–факт» считают по
  текущим данным активного проекта (кнопка «Рассчитать смету» им не нужна) и
  предупреждают, если смета дашборда устарела. На дашборде — строки «запас
  часов» и «NNE по факту» со ссылками; чувствительность отдельной страницей,
  чтобы не удлинять дашборд (в фазе 6 — вкладка «Результата»).
- Факт и «что если» — ключи проекта в `ui/state.py`: снимок в слоте, при
  загрузке каждый ключ задаётся явно.
- Редактор факта по правилу L-21: вход — неизменяемая база в сессии; она
  пересобирается только для нового виджета. Ключ виджета содержит номер,
  который растёт при загрузке проекта, «заполнить по плану» и строке вне
  плана: браузер хранит правки у прежнего виджета и не переносит их в другой
  проект.
- Дельты `st.metric` пишутся с ASCII-минусом: Streamlit выбирает по нему
  стрелку и цвет (с типографским «−» убыток показывался зелёной стрелкой
  вверх — нашлось на скриншоте).
- Демо: «Слайд 3: план и факт» одним проектом вместо двух; у товарного знака
  факт с работой партнёра вне плана. В демо 4 проекта, сметы по плану те же.

### Проверки

- Тест приватности: в сценарий пользователя добавлены ползунки, матрица,
  ввод факта и выгрузка файла с фактом.
- `docs/screenshots/phase-5/shots.js` (Playwright): ползунки «что если» и
  правка ячейки редактора факта переживают переключение проектов и смену
  страницы; факт одного проекта не попадает в другой. Ячейка холста
  glide-data-grid правится через скрытую таблицу для экранных читалок:
  фокус на ячейку, стрелки, Enter, ввод с паузой между символами.

## Последствия

- Цифры смет не изменились: снимки ядра, мост «было/стало» и golden-тесты
  фаз 2–4 прошли без `--update-snapshots`.
- Факт — только часы и выставленная сумма; фактические собственные расходы и
  освоение незавершённого проекта не моделируются.
- Формат чисел в новых экранах — `1 234 567 ₽` (`ui.labels.money`), в старых
  экранах — по-прежнему v0.3 до фазы 6; таблицы на узком экране прокручиваются
  по горизонтали.
