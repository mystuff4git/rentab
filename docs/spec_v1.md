2. UI — Streamlit, но отполированный: тема, онбординг, понятные экраны, аккуратные графики.
3. Новые фичи: (а) план vs факт и анализ чувствительности, (б) коммерческое предложение

4. Никакие данные фирмы не хранятся на сервере.

## Известные проблемы v0.3, которые надо исправить (проверь каждую сам по коду)
Методология:
1. Себестоимость часа (cost_rate) считается от КОНТРАКТНЫХ часов, а накладные — от
   БИЛЛИРУЕМЫХ. Стоимость небиллируемого времени юристов (при утилизации 60–75%) нигде не
   возмещается, поэтому цены систематически занижены. Нужно перейти на себестоимость
   биллируемого часа с учётом утилизации (формулы ниже).
2. НДС считается как расход фирмы (`taxable_base × vat_rate` вычитается из NNE). Это неверно:
   НДС начисляется сверх цены (или выделяется изнутри как r/(1+r), если цена «включая НДС»),
   это не доход и не расход фирмы. NNE считается от выручки без НДС.
3. Фикс-прайс ищется итерациями, хотя есть закрытые формулы (ниже).
4. Светофор по этапам: выручка делится пропорционально ЧАСАМ, а не стоимости часов; маржа
   этапа берётся ДО налога, а сравнивается с целевой маржей ПОСЛЕ налога; собственные расходы
   по этапам не распределяются.
5. На этапе только один исполнитель (`stage["executor"]`), поэтому пирамиду «партнёр
   проверяет 2 ч, юрист делает 10 ч» смоделировать нельзя.
6. Режим «Оба» (РФ+РК): пошлины в KZT складываются с RUB без конвертации; курс 0.18 захардкожен.
7. Налоговая логика дублируется (`calculator.calculate_tax` и `jurisdiction.TaxCalculator`);
   `ExpenseManager.get_overheads_allocated(direct_costs)` на самом деле получает часы.
Ставки и справочники:
8. НДФЛ сделан по шкале 13/15% с порогом 5 млн — это шкала 2021–2024. Взносы взяты плоскими 30%,
   без единой предельной базы и пониженных тарифов. Для УСН 15% нет минимального налога 1%.
   НПД не проверяет ограничения (нет сотрудников, запрет агентских договоров, лимит дохода).
   Для РК, похоже, не учтён социальный налог ТОО; в 2026 году в РК действует новый Налоговый кодекс.
   ВСЕ ставки 2026 года нужно перепроверить по первоисточникам (см. фазу 3).
9. Каталоги пошлин Роспатента и Казпатента пустые: все `amount = 0` с `# TODO`.
Продукт и безопасность:
10. Профиль фирмы (зарплаты, ставки) пишется в `data/firm_profile.json` НА СЕРВЕРЕ. На Streamlit
    Cloud это общий файл для всех посетителей. Это утечка данных и прямое противоречие тезису
    о 152-ФЗ. Убрать полностью.
11. Деньги во float, данные в dict без схем, `__pycache__` в git, тест — скрипт, а не pytest.

## Целевая методология (источник истины — `docs/methodology.md`, его создаёшь ты)
Обозначения: i — сотрудник, s — этап, a — назначение (сотрудник на этапе с часами h_a).

Себестоимость:
- full_cost_i (мес.) = оклад_i + взносы работодателя_i (с учётом предельной базы и тарифов
  юрисдикции; для партнёров-собственников без оклада задаётся «нормативное вознаграждение
  партнёра» по Майстеру, чтобы отделить оплату труда партнёра от прибыли фирмы).
- billable_capacity_i = contract_hours_i × target_utilization_i (по умолчанию 0.65, редактируется).
- cost_rate_i = full_cost_i / billable_capacity_i (себестоимость БИЛЛИРУЕМОГО часа).
  В UI показывать обе величины (за контрактный и за биллируемый час) и разницу между ними
  как «стоимость недозагрузки».
- overhead_rate = Σ накладных фирмы в месяц / Σ_i billable_capacity_i (по всей фирме).
- Labor_proj = Σ_a cost_rate_i(a) × h_a;  OH_proj = overhead_rate × Σ_a h_a;
  Own_proj = собственные (неперевыставляемые) расходы проекта.
- C = Labor_proj + OH_proj + Own_proj.

Выручка, НДС, пошлины:
- R = выручка за услуги БЕЗ НДС (только она — доход фирмы).
- VAT = R × vat_rate (если цена задана «включая НДС»: R = P_gross / (1 + vat_rate)).
- Пошлины и иные перевыставляемые расходы D — транзит: не входят в R, не облагаются,
  выделяются в КП отдельной строкой «возмещаемые расходы».
- К оплате клиентом = R + VAT + D.

Налог на доход/прибыль (t — ставка режима):
- база «доходы» (УСН 6%, НПД, АУСН «доходы»): Tax = t × R.
- база «доходы − расходы» (УСН 15%, ОСНО, ОУР РК): Tax = max(t × (R − C), min_tax(R)),
  где min_tax — например, 1% выручки для УСН 15%. Налог на уровне проекта — это аппроксимация
  (аллокация годового налога на проект); так и написать в методологии.
- NNE = R − C − Tax. Маржа m = NNE / R.

Модели ценообразования:
- Почасовая: R = Σ_a billing_rate_i(a) × h_a.
- Фикс (задана целевая маржа m*):
    база «доходы»:             P = C / (1 − m* − t)
    база «доходы − расходы»:   P = C × (1 − t) / (1 − t − m*)
    при минимальном налоге:    взять большее из решений, проверить условие применимости;
    при знаменателе ≤ 0 — понятная ошибка «цель недостижима при этом режиме».
- Фикс с потолком (capped fee): R = min(Σ billing_rate × h, cap).
- Blended rate = Σ billing_rate × h / Σ h; Leverage = часы младших / часы старших.

Этапы:
- Ключ распределения выручки — теневая стоимость этапа V_s = Σ_{a∈s} billing_rate × h_a
  (а не часы). R_s = R × V_s / Σ V.
- C_s = Labor_s + overhead_rate × H_s + Own_s (собственные расходы привязываются к этапу,
  а без привязки распределяются пропорционально V_s).
- Tax_s распределяется по той же логике, что и общий налог; m_s = (R_s − C_s − Tax_s) / R_s.
- Светофор: green, если m_s ≥ m*; yellow, если 0 < m_s < m*; red, если m_s ≤ 0. Пороги — константы.

Аналитика:
- Точка безубыточности по часам: сколько дополнительных часов (с заданным ролевым миксом или
  конкретной ролью) можно потратить при зафиксированной цене до NNE = 0.
- Торнадо-диаграмма: влияние ±X% по часам, ставкам, утилизации, накладным, курсу на NNE.
- План vs факт: ввод фактических часов по назначениям, пересчёт NNE и маржи по факту,
  realization rate (выставлено / теневая стоимость фактических часов), списания,
  перерасход по этапам и ролям.
- Сравнение: одна матрица «модель ценообразования × налоговый режим» → цена для клиента,
  к оплате, NNE, маржа. Недоступные режимы помечаются с причиной (валидатор применимости
  режимов: лимиты дохода и штата, запрет найма и агентских договоров для НПД и т.п.).

Иллюстративный набор данных — слайд 3 моей защиты (сделай из него demo-сценарий и golden-тест,
явно задокументировав, как меняются цифры после исправления учёта НДС):
выручка 300 000 ₽, УСН 6% + НДС 5%, накладные 100 ₽/ч; ставки себестоимости
Партнёр 4000, Юрист 1500, Стажёр 500 ₽/ч;
план: П 5 ч / Ю 15 ч / С 20 ч (ФОТ 52 500, накладные 4 000, в старой логике маржа 210 500);
факт «партнёр тянет проект»: П 62 ч / Ю 15 ч / С 10 ч (ФОТ 275 500, накладные 8 700,
в старой логике −17 200).

```
    duties/catalog.py + data/rospatent_2026.yaml, kazpatent_2026.yaml
    fx.py                   # курсы ЦБ РФ / НБРК с кэшем и ручным фолбэком
    export/xlsx.py, docx.py, pdf.py, templates/
    io.py                   # импорт/экспорт профиля и проектов в JSON (с версией схемы)
  app/
    Home.py + pages/ (Фирма, Проект, Результат, Сравнение, План–факт), ui/ (компоненты, тема)
    .streamlit/config.toml
  tests/                    # unit на каждый модуль, golden-сценарии, property-тесты
  docs/methodology.md, rates_verification.md, ROADMAP.md, adr/
  .github/workflows/ci.yml  # ruff + mypy + pytest на каждый PR
  README.md (RU + краткий EN), LICENSE (MIT), CHANGELOG.md, Dockerfile
```
Правила: `rentab_core` не импортирует streamlit; UI только вызывает ядро и рисует.
Деньги — Decimal внутри ядра, округление только на выводе. Идентификаторы в коде — на английском,
докстринги и комментарии — на русском, весь интерфейс — на русском. Без магических чисел:
ставки — в YAML-реестре, пороги и дефолты — в именованных константах.
