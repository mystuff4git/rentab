# Методология расчёта Rentab

Источник истины по формулам ядра `rentab_core` (фаза 2). Код и тесты следуют
этому документу; при изменении формулы сначала правится он. Методологическая
основа — Д. Майстер, «Управление фирмой, оказывающей профессиональные услуги»:
себестоимость биллируемого часа, утилизация, рычаг, NNE.

Ставки налогов в примерах взяты из реестра `rates/*.yaml` (значения v0.3,
`needs_review: true`; сверка по первоисточникам — фаза 3). Ссылки вида
`L-NN` ведут в [`legacy_audit.md`](legacy_audit.md).

## 1. Формулы на одном экране

```
Себестоимость
  K_i  = H_i × u_i                     биллируемая ёмкость сотрудника, ч/мес
  c_i  = W_i / K_i                     себестоимость биллируемого часа (cost_rate)
  ĉ_i  = W_i / H_i                     себестоимость контрактного часа
  ρ    = Σ OH / Σ_i K_i                ставка накладных на биллируемый час
  C    = Σ_a c_i(a)·h_a + ρ·Σ_a h_a + Own

Выручка и оплата
  R    — выручка за услуги без НДС; если цены «включая НДС»: R = P / (1 + v)
  VAT  = v × R                         начисляется сверху, не доход и не расход фирмы
  К оплате = R + VAT + D               D — возмещаемые расходы (пошлины), транзит

Налог
  «доходы»:            Tax = t × R
  «доходы − расходы»:  Tax = max( t × max(R − C, 0), t_min × R )

Результат
  NNE  = R − C − Tax                   m = NNE / R

Цена
  почасовая:     R = Σ_a b_i(a)·h_a
  с потолком:    R = min(Σ_a b_i(a)·h_a, cap)
  фикс, «доходы»:            P = C / (1 − m* − t)
  фикс, «доходы − расходы»:  P = max( C(1 − t) / (1 − t − m*),  C / (1 − t_min − m*) )

Этапы
  V_s  = Σ_{a∈s} b_i(a)·h_a            теневая стоимость этапа
  R_s  = R × V_s / Σ V
  C_s  = Labor_s + ρ·H_s + Own_s
  m_s  = (R_s − C_s − Tax_s) / R_s     green: m_s ≥ m*;  yellow: 0 < m_s < m*;  red: m_s ≤ 0
```

## 2. Обозначения

Индексы: `i` — сотрудник, `s` — этап, `a` — назначение (сотрудник `i(a)` на
этапе `s(a)` с часами `h_a`). На этапе может быть сколько угодно назначений.

| Символ | Что это | Поле в ядре |
|---|---|---|
| `W_i` | Полная стоимость сотрудника в месяц | `Employee.compensation` |
| `H_i` | Контрактные часы в месяц (по умолчанию 168) | `Employee.contract_hours_per_month` |
| `u_i` | Целевая утилизация, доля в (0; 1] (по умолчанию 0,65) | `Employee.target_utilization` |
| `K_i` | Биллируемая ёмкость, `H_i × u_i` | вычисляется |
| `c_i` | Себестоимость биллируемого часа | вычисляется (`cost_rate`) |
| `ĉ_i` | Себестоимость контрактного часа | вычисляется |
| `b_i` | Ставка для клиента за час | `Employee.billing_rate` |
| `OH` | Накладные фирмы за месяц | `Firm.overheads` |
| `ρ` | Ставка накладных на биллируемый час | вычисляется (`overhead_rate`) |
| `Labor` | Трудозатраты проекта, `Σ c·h` | вычисляется |
| `Own` | Собственные (неперевыставляемые) расходы проекта | `Disbursement`, тип `own` |
| `C` | Издержки проекта, `Labor + ρ·Σh + Own` | вычисляется |
| `R` | Выручка за услуги без НДС | вычисляется по модели цены |
| `v` | Ставка НДС режима | реестр ставок |
| `VAT` | НДС, предъявляемый клиенту | вычисляется |
| `D` | Возмещаемые расходы (пошлины) | `Disbursement`, тип `billable` |
| `t`, `t_min` | Ставка налога режима и ставка минимального налога | реестр ставок |
| `Tax` | Налог на доход или прибыль по проекту | вычисляется |
| `NNE`, `m` | Чистая прибыль проекта и маржа NNE | вычисляется |
| `m*` | Целевая маржа NNE | `Project.target_margin` (по умолчанию 0,30) |
| `V_s` | Теневая стоимость этапа | вычисляется |

Деньги внутри ядра — `Decimal` без округления; на выводе — до копейки
(тиына), «половина вверх». Все суммы расчёта приводятся к валюте проекта
(раздел 9).

## 3. Себестоимость (L-01, L-12)

### 3.1. Полная стоимость сотрудника

`W_i` — сколько сотрудник стоит фирме в месяц. Задаётся одним из двух способов:

- **Оклад и взносы**: `W_i = оклад_i × (1 + ставка взносов_i)`. Ставка взносов
  подставляется по стране трудоустройства сотрудника (валюта RUB — тариф РФ,
  KZT — отчисления РК) и редактируется. Предельная база и пониженные тарифы —
  фаза 3 (L-08).
- **Сумма в месяц**: `W_i` вводится напрямую. Так задаётся **нормативное
  вознаграждение партнёра** по Майстеру — рыночная цена его труда, если бы
  партнёр был наёмным юристом. Это отделяет оплату труда партнёра от прибыли
  фирмы: NNE остаётся доходом собственника на капитал и риск, а не скрытой
  зарплатой. Так же вводится стоимость подрядчика.

### 3.2. Себестоимость биллируемого часа

```
K_i = H_i × u_i
c_i = W_i / K_i           — себестоимость биллируемого часа (cost_rate)
ĉ_i = W_i / H_i           — себестоимость контрактного часа
c_i − ĉ_i = c_i × (1 − u_i)   — стоимость недозагрузки на час
```

Клиенту продаётся только биллируемое время. Остальные `1 − u_i` рабочего
времени (обучение, развитие бизнеса, внутренние задачи, простои) фирма всё
равно оплачивает, и возместить их можно только через цену проданных часов.
Поэтому в расчёт проекта идёт `c_i`, а не `ĉ_i`.

В v0.3 калькулятор ФОТ делил `W_i` на контрактные часы, то есть давал `ĉ_i`
(L-01). При утилизации 65% это занижает себестоимость часа в 1/0,65 ≈ 1,54 раза.

Утилизация задаётся по каждому сотруднику: у партнёров она обычно ниже
(управление, привлечение клиентов). Допустимы значения от 0 (не включая) до 1;
переработки моделируются увеличением `H_i`.

На уровне проекта стоимость недозагрузки `Σ_a (c_i − ĉ_i)·h_a` показывается
отдельно: это сумма, которую v0.3 не включал в себестоимость.

### 3.3. Ставка накладных

```
ρ = Σ_k OH_k(мес) / Σ_i K_i
```

- Знаменатель — биллируемая ёмкость **всей фирмы**, сумма `K_i` по команде.
  Отдельного поля «биллируемые часы фирмы» больше нет: ёмкость выводится из
  команды.
- Ежемесячные накладные входят как есть, годовые — 1/12, разовые не входят.
- Накладные в разных валютах приводятся к валюте проекта (раздел 9).
- В команду входят только сотрудники, чьи часы продаются клиентам. Ассистент,
  бухгалтер и другие небиллируемые сотрудники — это накладные.

Теперь числитель и знаменатель согласованы: `c_i` и `ρ` оба считаются на
биллируемый час.

### 3.4. Издержки проекта

```
Labor = Σ_a c_i(a) × h_a
OH_proj = ρ × Σ_a h_a
Own = Σ собственных расходов проекта
C = Labor + OH_proj + Own
```

Собственный расход — тот, что фирма несёт за свой счёт и клиенту не
перевыставляет (курьер, нотариальный перевод, командировка). Категория
«Прочее» из v0.3 — тоже собственный расход: она входит в `Own`, уменьшает NNE
и закладывается в фикс-цену (L-12; в v0.3 такие расходы терялись).

## 4. Выручка, НДС и возмещаемые расходы (L-02)

### 4.1. Выручка

`R` — выручка за услуги **без НДС**. Только она — доход фирмы. Как получается
`R`, определяет модель цены (раздел 7).

У проекта есть режим ввода цен (`Project.vat_mode`), он относится к ставкам
для клиента, потолку и согласованной фикс-цене:

- **без НДС** (по умолчанию): введённые цены — это `R`, НДС начисляется сверху;
- **включая НДС**: введённая цена `P` уже содержит НДС, `R = P / (1 + v)`.

Цена «издержки + маржа» всегда вычисляется как `R`: от неё считаются маржа и
налог. Клиенту она показывается без НДС и с НДС.

### 4.2. НДС

```
VAT = v × R
```

НДС фирма получает от клиента и перечисляет в бюджет. Это не её доход и не её
расход: NNE от НДС не зависит, в фикс-цену НДС не закладывается. В v0.3 НДС
вычитался из NNE и закладывался в фикс-цену как налог фирмы (L-02).

Если режим без НДС (`v = 0`), то `VAT = 0`.

### 4.3. Возмещаемые расходы

`D` — пошлины Роспатента и Казпатента и другие расходы, которые фирма платит
за клиента и перевыставляет ему. Это транзит:

- не входят в `R` и не влияют на маржу;
- не облагаются налогом на доход и НДС;
- в смете и КП — отдельная строка «Возмещаемые расходы».

```
К оплате клиентом = R + VAT + D
```

## 5. Налог на доход или прибыль

### 5.1. Две базы

```
«доходы»:            Tax = t × R
«доходы − расходы»:  Tax = max( t × max(R − C, 0), t_min × R )
```

| Режим | База | `t` | `t_min` | НДС `v` |
|---|---|---|---|---|
| УСН «доходы» | доходы | 6% | — | 0 / 5% / 7% |
| УСН «доходы − расходы» | доходы − расходы | 15% | 1% | 0 / 5% / 7% |
| АУСН «доходы» | доходы | 8% | — | 0 |
| НПД | доходы | 4% (физлица) / 6% (юрлица) | — | 0 |
| ОСНО | доходы − расходы | 25% | — | 22% |
| ОУР РК, ТОО (КПН) | доходы − расходы | 20% | — | 0 / 16% |
| ОУР РК, ИП (ИПН) | доходы − расходы | 10% | — | 0 / 16% |

`t_min` — минимальный налог УСН «доходы − расходы» (1% доходов, п. 6
ст. 346.18 НК РФ). В v0.3 его не было (L-08). Ставка добавляется в реестр
`ru_2026.yaml` с `needs_review: true`; ссылку на первоисточник ставит фаза 3.
Для режимов без минимального налога `t_min = 0`.

Налоговая база — выручка без НДС: и УСН, и налог на прибыль, и КПН считаются
от доходов без предъявленного покупателю НДС. Возмещаемые расходы `D` в базу
не входят.

### 5.2. Налог проекта — аппроксимация

Налог платится за год по фирме целиком, а не по проекту. `Tax` — это доля
годового налога, которую можно отнести на проект, если проект типичен для
фирмы. Отсюда ограничения:

- минимальный налог сравнивается с налогом на прибыль по проекту, а не по году;
- убыток проекта не создаёт «отрицательного налога» на уровне проекта
  (`max(R − C, 0)`), хотя в годовом расчёте он уменьшил бы налог по другим
  проектам;
- все издержки `C` считаются признаваемыми расходами (раздел 14).

## 6. NNE, маржа и показатели (L-15)

```
NNE = R − C − Tax
m = NNE / R                        (при R = 0 маржа не определена и показывается как 0)
эффективная ставка налога = Tax / R
стоимость недозагрузки = Σ_a (c_i − ĉ_i) × h_a
средневзвешенная ставка (blended rate) = Σ_a b_i·h_a / Σ_a h_a
рычаг (leverage) = часы младших (младший юрист, стажёр) / часы старших (партнёр, старший юрист)
```

Все относительные показатели проекта считаются от одной базы — `R`. В v0.3
эффективная ставка налога делилась на услуги + пошлины, а маржа — на услуги
(L-15).

## 7. Модели ценообразования (L-03)

### 7.1. Почасовая

```
R = Σ_a b_i(a) × h_a               (÷ (1 + v), если ставки «включая НДС»)
```

### 7.2. Почасовая с потолком (capped fee)

```
R = min(Σ_a b_i(a) × h_a, cap)
списание = Σ_a b_i(a) × h_a − R
```

`cap` указывается в том же режиме НДС, что и ставки.

### 7.3. Фиксированная цена «издержки + маржа»

Задана целевая маржа `m*`. Ищется наименьшая выручка `P = R`, при которой
`NNE = m* × P`.

**База «доходы».** `P − C − tP = m*P`, откуда

```
P = C / (1 − m* − t)
```

**База «доходы − расходы» без минимального налога** (при `P ≥ C`):
`P − C − t(P − C) = m*P`, откуда

```
P_A = C(1 − t) / (1 − t − m*)
```

**С минимальным налогом.** Если работает минимальный налог,
`P − C − t_min·P = m*P`, откуда

```
P_B = C / (1 − t_min − m*)
```

`NNE(P) = min( (1 − t)(P − C), (1 − t_min)P − C ) − m*P`. Обе ветви растут с
`P`, поэтому `NNE ≥ m*P` ровно тогда, когда `P ≥ P_A` и `P ≥ P_B`. Наименьшая
такая цена:

```
P = max(P_A, P_B)
```

Отдельная проверка применимости не нужна: при `P = max(P_A, P_B)` автоматически
работает та ветвь налога, решением которой является `P`. Минимальный налог
определяет цену при низкой целевой марже: для УСН 15% / 1% — при
`m* < 0,0085 / 0,15 ≈ 5,7%` (в том числе для цены безубыточности `m* = 0`).

**Когда цели не достичь.** Нужны положительные знаменатели: `1 − m* − t > 0`
(и `1 − t_min − m* > 0` для минимального налога). Иначе ядро бросает
`FixedPriceError` с текстом «Целевая маржа m* недостижима при режиме X:
маржа + ставка налога = … ≥ 100%». При `C = 0` цена равна 0.

В v0.3 цена искалась итерациями, а НДС входил в знаменатель как налог фирмы:
`C / (1 − m* − t − v)` (L-02, L-03). Итерации совпадали с закрытыми формулами
до копейки, так что цифры меняет только уход `v` из знаменателя.

### 7.4. Согласованная фиксированная цена

Цена уже согласована с клиентом (`FixedPricing.price`): `R = price`
(или `price / (1 + v)` в режиме «включая НДС»), а `NNE` и `m` — следствие.
Так считается слайд 3 (раздел 12), так же в фазе 5 будут считаться план–факт и
точка безубыточности при зафиксированной цене. `m*` здесь — только порог
светофора.

## 8. Этапы и светофор (L-04, L-05, L-19)

### 8.1. Назначения

Этап — это набор назначений «сотрудник × часы». Пирамида «партнёр проверяет
2 ч, юрист делает 8 ч» — один этап с двумя назначениями. В v0.3 на этапе был
один исполнитель, и пирамиду приходилось задавать одноимёнными этапами (L-05).
Названия этапов в проекте уникальны.

### 8.2. Выручка этапа — по теневой стоимости

```
V_s = Σ_{a∈s} b_i(a) × h_a
R_s = R × V_s / Σ_s V_s
```

Теневая стоимость — сколько этап стоил бы клиенту по ставкам. Час партнёра
весит больше часа стажёра; деление по часам (v0.3) переносило выручку с
партнёрских этапов на стажёрские, и светофор показывал проблему не там (L-04).

Если ставки для клиента не заданы ни у кого (`Σ V_s = 0`, чистый «издержки +
маржа»), ключом служат трудозатраты `Labor_s`, а если и их нет — часы `H_s`.

В почасовой модели со ставками без НДС `R_s = V_s`, с потолком — доля `cap`
по теневой стоимости.

### 8.3. Издержки этапа

```
C_s = Labor_s + ρ × H_s + Own_s
```

Собственный расход можно привязать к этапу (`Disbursement.stage`). Расходы без
привязки распределяются по тому же ключу, что и выручка (`V_s / Σ V`).
В v0.3 собственные расходы этапам не доставались вовсе (L-04).

### 8.4. Налог этапа

Распределение повторяет логику налога проекта, и `Σ_s Tax_s = Tax` всегда:

- база «доходы»: `Tax_s = t × R_s`;
- база «доходы − расходы», налог проекта равен налогу на прибыль `t(R − C) > 0`:
  `Tax_s = t × (R_s − C_s)`. Убыточный этап получает отрицательный налог: он
  уменьшает налог по проекту;
- иначе (работает минимальный налог или налог нулевой): `Tax_s = Tax × R_s / R`.

### 8.5. Маржа этапа и светофор

```
m_s = (R_s − C_s − Tax_s) / R_s        (при R_s = 0 — 0)
```

| Цвет | Условие |
|---|---|
| green | `m_s ≥ m*` |
| yellow | `0 < m_s < m*` |
| red | `m_s ≤ 0` |

Пороги — именованные константы ядра. Маржа этапа считается **после** налога и
сравнивается с целевой маржой после налога (в v0.3 сравнивалась маржа до
налога, L-04). Светофор работает для всех моделей цены; в почасовой `m*` — порог
сравнения, цену он не определяет. Строки этапов на дашборде показывают `m_s`,
а не `(ставка − себестоимость) / ставка` (L-19).

## 9. Валюты (L-06)

- Валюта проекта — валюта страны расчёта налога: RUB для РФ, KZT для РК. В
  режиме «Оба» страну выбирают на проекте.
- У каждой денежной величины на входе своя валюта: у оклада и ставок сотрудника,
  у накладных, у расходов проекта.
- Курсы задаются как цена единицы валюты в рублях (`₽ за 1 ₸`, `₽ за 1 $`), так
  их публикует ЦБ РФ. Пересчёт:

```
amount_target = amount_source × rub_per(source) / rub_per(target),   rub_per(RUB) = 1
```

- Все входы приводятся к валюте проекта **до** расчёта: `W_i`, `b_i`, `OH`,
  `Own`, `D`. Ставка накладных `ρ` считается в валюте проекта.
- Если нужен курс, которого нет, ядро бросает понятную ошибку («Укажите курс
  ₽ за 1 ₸»), а не складывает суммы как есть.
- В фазе 2 курс вводится вручную. Загрузка курсов ЦБ РФ и НБРК с кэшем —
  фаза 3 (`fx.py`).

**Пример.** Фирма в режиме «Оба», проект считается по РФ, курс 0,18 ₽ за 1 ₸
(условный). Аренда в Москве 120 000 ₽ и в Алматы 300 000 ₸ в месяц дают
накладные `120 000 + 300 000 × 0,18 = 174 000 ₽`; v0.3 складывал их в
420 000 «рублей». Пошлины Роспатента 38 500 ₽ и Казпатента 120 000 ₸ дают
`D = 38 500 + 21 600 = 60 100 ₽`, а не 158 500.

## 10. Пример 1. Почасовая модель

### 10.1. Фирма

Команда — три человека с параметрами слайда 3 (себестоимость часа 4 000 /
1 500 / 500 ₽). Для круглых чисел у всех `H = 160` ч и `u = 62,5%`, то есть
`K = 100` ч в месяц.

| Сотрудник | Роль | `W`, ₽/мес | `ĉ = W/H`, ₽/ч | `c = W/K`, ₽/ч | Недозагрузка, ₽/ч | `b`, ₽/ч |
|---|---|---|---|---|---|---|
| Партнёр | партнёр | 400 000 (нормативное вознаграждение) | 2 500 | 4 000 | 1 500 | 10 000 |
| Юрист | младший юрист | 150 000 (оклад + взносы) | 937,5 | 1 500 | 562,5 | 5 000 |
| Стажёр | стажёр | 50 000 | 312,5 | 500 | 187,5 | 2 000 |

Накладные 30 000 ₽ в месяц, ёмкость фирмы `3 × 100 = 300` ч:
`ρ = 30 000 / 300 = 100 ₽/ч`.

### 10.2. Проект «Регистрация товарного знака»

| Этап | Назначения | `H_s`, ч | `Labor_s`, ₽ | `V_s`, ₽ |
|---|---|---|---|---|
| 1. Анализ охраноспособности | Партнёр 2 ч, Юрист 8 ч | 10 | 2·4 000 + 8·1 500 = 20 000 | 2·10 000 + 8·5 000 = 60 000 |
| 2. Подготовка и подача заявки | Юрист 4 ч, Стажёр 10 ч | 14 | 4·1 500 + 10·500 = 11 000 | 4·5 000 + 10·2 000 = 40 000 |
| Итого | | 24 | 31 000 | 100 000 |

Расходы проекта:

- пошлина за подачу заявки (условно) 15 000 ₽ — возмещаемый расход `D`;
- нотариальный перевод доверенности 1 800 ₽ — собственный расход этапа 2.

Издержки:

```
Labor   = 31 000
OH_proj = 100 × 24 = 2 400
Own     = 1 800
C       = 35 200 ₽
```

Стоимость недозагрузки `= 2·1 500 + 12·562,5 + 10·187,5 = 11 625 ₽`: на столько
v0.3 занизил бы себестоимость этого проекта.

Средневзвешенная ставка `100 000 / 24 = 4 166,67 ₽/ч`, рычаг `(12 + 10) / 2 = 11`.

### 10.3. Выручка и оплата

Ставки без НДС: `R = ΣV = 100 000 ₽`. В обоих режимах ниже НДС 5%:

```
VAT = 0,05 × 100 000 = 5 000
К оплате = 100 000 + 5 000 + 15 000 = 120 000 ₽
```

(Если бы ставки были «включая НДС»: `R = 100 000 / 1,05 = 95 238,10`,
`VAT = 4 761,90`.)

| | УСН «доходы» 6% + НДС 5% | УСН «доходы − расходы» 15% + НДС 5% |
|---|---|---|
| `R` | 100 000 | 100 000 |
| `C` | 35 200 | 35 200 |

| НДС (сверху, не влияет на NNE) | 5 000 | 5 000 |

Почасовая модель: `R_s = V_s`. Накладные этапа `ρ·H_s`: 1 000 и 1 400 ₽.

|---|---|---|---|---|---|---|
| 1 | 60 000 | 20 000 + 1 000 = 21 000 | 3 600 | 35 400 / 59,00% 🟢 | 5 850 | 33 150 / 55,25% 🟢 |

## 11. Пример 2. Фиксированная цена

Тот же проект и фирма (`C = 35 200 ₽`, `D = 15 000 ₽`), целевая маржа
`m* = 30%`.

### 11.1. База «доходы»: УСН 6% + НДС 5%

```
P = C / (1 − m* − t) = 35 200 / (1 − 0,30 − 0,06) = 35 200 / 0,64 = 55 000 ₽
Tax = 0,06 × 55 000 = 3 300
NNE = 55 000 − 35 200 − 3 300 = 16 500 = 30% × 55 000   ✓
VAT = 0,05 × 55 000 = 2 750
К оплате = 55 000 + 2 750 + 15 000 = 72 750 ₽
```

### 11.2. База «доходы − расходы»: УСН 15% (мин. 1%) + НДС 5%

```
P_A = C(1 − t) / (1 − t − m*) = 35 200 × 0,85 / 0,55 = 54 400
P_B = C / (1 − t_min − m*)    = 35 200 / 0,69        = 51 014,49
P = max(P_A, P_B) = 54 400 ₽
Tax = max(0,15 × (54 400 − 35 200); 0,01 × 54 400) = max(2 880; 544) = 2 880
NNE = 54 400 − 35 200 − 2 880 = 16 320 = 30% × 54 400   ✓
VAT = 2 720;  к оплате = 54 400 + 2 720 + 15 000 = 72 120 ₽
```

### 11.3. Когда цену определяет минимальный налог

Цена безубыточности (`m* = 0`) на УСН 15%:

```
P_A = 35 200 × 0,85 / 0,85 = 35 200
P_B = 35 200 / 0,99        = 35 555,56
P = 35 555,56 ₽;  Tax = 0,01 × 35 555,56 = 355,56 (налог на прибыль был бы 53,33);  NNE = 0
```

Безубыточная цена выше издержек на 1/99: даже без прибыли фирма платит
минимальный налог. Для сравнения, на УСН 6% цена безубыточности
`35 200 / 0,94 = 37 446,81 ₽`.

Цель недостижима при `m* ≥ 1 − t`: на УСН 6% — от 94%, на УСН 15% — от 85%.

### 11.4. Этапы

Выручка этапов делится по теневой стоимости 60 000 : 40 000.

| Этап | `C_s` | УСН 6%: `R_s` / `Tax_s` / NNE / `m_s` | УСН 15%: `R_s` / `Tax_s` / NNE / `m_s` |
|---|---|---|---|
| 1 | 21 000 | 33 000 / 1 980 / 10 020 / 30,36% 🟢 | 32 640 / 1 746 / 9 894 / 30,31% 🟢 |
| 2 | 14 200 | 22 000 / 1 320 / 6 480 / 29,45% 🟡 | 21 760 / 1 134 / 6 426 / 29,53% 🟡 |
| Σ | 35 200 | 55 000 / 3 300 / 16 500 | 54 400 / 2 880 / 16 320 |

Этап 2 чуть ниже цели: на него отнесён нотариальный перевод (1 800 ₽).

Если поделить ту же цену 55 000 ₽ по часам, как v0.3 (10 : 14), и сравнить
маржу до налога без собственных расходов, цвета поменяются местами: этап 1 —
`R = 22 916,67`, маржа 8,36% 🟡; этап 2 — `R = 32 083,33`, маржа 61,35% 🟢.
Партнёрский этап выглядел бы проблемным, хотя проблемы в нём нет.

v0.3 считал бы себестоимость часа от контрактных часов (2 500 / 937,5 /
312,5 ₽): `Labor = 19 375`, `C = 23 575 ₽` (при тех же 300 биллируемых часах

## 12. Слайд 3 защиты ВКР в новой методологии

Golden-сценарий (`tests/core/test_golden_slide3.py`). Данные слайда:
выручка 300 000 ₽, УСН 6% + НДС 5%, накладные 100 ₽/ч, себестоимость часа

Себестоимость часа на слайде — это уже себестоимость **биллируемого** часа
(ФОТ на слайде = Σ ставка × часы). В golden-тесте фирма из раздела 10.1 с
накладными 30 000 ₽/мес даёт ровно эти ставки и 100 ₽/ч.

### 12.1. План и факт

Принимается, что 300 000 ₽ — цена **без НДС**: на слайде НДС посчитан как
`5% × 300 000 = 15 000`, то есть сверху (открытый вопрос из ROADMAP).

| | План v0.3 | План | Факт v0.3 | Факт |
|---|---|---|---|---|
| Часы (П / Ю / С) | 5 / 15 / 20 | 5 / 15 / 20 | 62 / 15 / 10 | 62 / 15 / 10 |
| `R` | 300 000 | 300 000 | 300 000 | 300 000 |
| НДС 5% | 15 000 — из NNE | 15 000 — сверху | 15 000 — из NNE | 15 000 — сверху |
| К оплате | 300 000 | **315 000** | 300 000 | **315 000** |
| ФОТ (`Labor`) | 52 500 | 52 500 | 275 500 | 275 500 |
| Накладные | 4 000 | 4 000 | 8 700 | 8 700 |
| УСН 6% | 18 000 | 18 000 | 18 000 | 18 000 |
| **NNE** | 210 500 | **225 500** | −17 200 | **−2 200** |
| Маржа | 70,17% | 75,17% | −5,73% | −0,73% |

Каждое NNE выросло ровно на 15 000 ₽ — сумму НДС, которую платит клиент, а не

## 13. Что изменилось по сравнению с v0.3

| ID | Было в v0.3 | Стало | Что меняется в цифрах |
|---|---|---|---|
| L-01 | `cost_rate = W / H`; ставка накладных — на биллируемые часы, введённые для фирмы | `c = W / (H·u)`; `ρ = ΣOH / ΣK`, ёмкость из команды | Трудозатраты растут в `1/u`; ставка накладных — по ёмкости команды |
| L-02 | НДС вычитается из NNE и закладывается в фикс-цену; клиенту НДС не выставляется | НДС сверху, к оплате `R + VAT + D` | NNE растёт на НДС; фикс-цена падает; «к оплате» растёт на НДС |
| L-03 | Итерации; нет минимального налога | Закрытые формулы; `max(P_A, P_B)` | УСН 15%: цена и налог при низкой марже |
| L-04 | Этапы по часам, маржа до налога, без собственных расходов | По теневой стоимости, после налога, с `Own_s` | Выручка, издержки, маржа и цвет этапов |
| L-05 | Один исполнитель на этап | Несколько назначений | Пирамида — один этап; часы этапа не суммируются по названию |
| L-06 | RUB, KZT и USD складываются как есть | Пересчёт в валюту проекта по курсу | Накладные, пошлины, ставки в режиме «Оба» |
| L-12 | «Прочее» теряется | «Прочее» = собственный расход | NNE падает, фикс-цена растёт на эту сумму |
| L-15 | Налог / (услуги + пошлины) | Налог / `R` | Эффективная ставка налога |
| L-19 | Маржа строки этапа `(b − c) / b` | `m_s` с накладными, налогом и `Own_s` | Маржа строк дашборда |

Как цифры v0.3 переводятся в новую модель для таблицы «было/стало»
(characterization-тесты, адаптер `tests/characterization/core_adapter.py`):

- `cost_rate` v0.3 — себестоимость контрактного часа (так её считал калькулятор
  ФОТ v0.3), поэтому `W = cost_rate × H`, `H = 168` (норма v0.3), `u = 0,65`
  (значение по умолчанию);
- биллируемые часы фирмы v0.3 не переносятся: ёмкость считается по команде;
- одноимённые этапы v0.3 — это один этап с несколькими назначениями (L-05);
- «Прочее» — собственный расход (L-12);
- ставки и оклады команды — в валюте страны фирмы (в режиме «Оба» — RUB);
  курс тенге — `exchange_rate_rub_per_kzt` сценария.

## 14. Допущения и ограничения

- **Налог проекта — аппроксимация** годового налога (раздел 5.2).
- **Все издержки признаются расходами** для базы «доходы − расходы». Если
  нормативное вознаграждение партнёра на деле выплачивается дивидендами, оно
  расходом не является, и налог по проекту занижен.
- **Уменьшение налога УСН «доходы» на страховые взносы** (до 50% для
  работодателей) не моделируется: налог на этой базе — оценка сверху.
- **Входящий НДС** не моделируется: накладные и собственные расходы вводятся
  в сумме, которую фирма фактически несёт.
- **Пошлины — по агентской схеме.** Если фирма перевыставляет их как часть
  цены услуги, а не как возмещение, они могут войти в доход и базу НДС; модель
  этот случай не покрывает.
- **Разовые накладные** не распределяются по проектам.
- **Взносы** — плоская ставка от оклада; предельная база, пониженные тарифы и
  социальный налог РК — фаза 3. Ставки в примерах помечены `needs_review`.
- **Округление.** Внутри расчёта округления нет. В документах для клиента
  строка «К оплате» должна быть суммой уже округлённых строк (фаза 7), иначе
  возможно расхождение в 1 коп.
