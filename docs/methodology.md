# Методология расчёта Rentab

Источник истины по формулам ядра `rentab_core` (фазы 2–3, аналитика — фаза 5). Код и тесты следуют
этому документу; при изменении формулы сначала правится он. Методологическая
основа — Д. Майстер, «Управление фирмой, оказывающей профессиональные услуги»:
себестоимость биллируемого часа, утилизация, рычаг, NNE.

Ставки налогов и взносов в примерах взяты из реестра `rates/*.yaml` (ставки
2026 года). Первоисточник, уверенность и признак «нужна проверка юристом» по
каждой ставке — в [`rates_verification.md`](rates_verification.md). Ссылки вида
`L-NN` ведут в [`legacy_audit.md`](legacy_audit.md).

## 1. Формулы на одном экране

```
Себестоимость
  K_i  = H_i × u_i                     биллируемая ёмкость сотрудника, ч/мес
  c_i  = W_i / K_i                     себестоимость биллируемого часа (cost_rate)
  ĉ_i  = W_i / H_i                     себестоимость контрактного часа
  ρ    = Σ OH / Σ_i K_i                ставка накладных на биллируемый час
  C    = Σ_a c_i(a)·h_a + ρ·Σ_a h_a + Own

Выручка и оплата
  R    — выручка за услуги без НДС; если цены «включая НДС»: R = P / (1 + v)
  VAT  = v × R                         начисляется сверху, не доход и не расход фирмы
  К оплате = R + VAT + D               D — возмещаемые расходы (пошлины), транзит

Налог
  «доходы»:            Tax = max( t × R − S,  (1 − κ) × t × R )      S — взносы на часах проекта
  «доходы − расходы»:  Tax = max( t × max(R − C + N, 0), t_min × R )  N — вознаграждение из прибыли

Результат
  NNE  = R − C − Tax                   m = NNE / R

Цена
  почасовая:     R = Σ_a b_i(a)·h_a
  с потолком:    R = min(Σ_a b_i(a)·h_a, cap)
  фикс, «доходы»:            P = max( (C − S) / (1 − t − m*),  C / (1 − (1 − κ)t − m*) )
  фикс, «доходы − расходы»:  P = max( (C(1 − t) + tN) / (1 − t − m*),  C / (1 − t_min − m*) )

Этапы
  V_s  = Σ_{a∈s} b_i(a)·h_a            теневая стоимость этапа
  R_s  = R × V_s / Σ V
  C_s  = Labor_s + ρ·H_s + Own_s
  m_s  = (R_s − C_s − Tax_s) / R_s     green: m_s ≥ m*;  yellow: 0 < m_s < m*;  red: m_s ≤ 0

Аналитика (разделы 16–19)
  запас часов:   NNE(x) = min_j (α_j − β_j·x);   x* = min{ α_j / β_j : β_j > 0 }
  торнадо:       ΔNNE_f(±X) = NNE(f × (1 ± X)) − NNE
  реализация:    R / V;   списание = max(V − R, 0);   премия = max(R − V, 0)
  перерасход:    Δh = h^f − h^p;   Δcost_i = (c_i + ρ)·Δh_i
```

## 2. Обозначения

Индексы: `i` — сотрудник, `s` — этап, `a` — назначение (сотрудник `i(a)` на
этапе `s(a)` с часами `h_a`). На этапе может быть сколько угодно назначений.

| Символ | Что это | Поле в ядре |
|---|---|---|
| `W_i` | Полная стоимость сотрудника в месяц | `Employee.compensation` |
| `H_i` | Контрактные часы в месяц (по умолчанию 168) | `Employee.contract_hours_per_month` |
| `u_i` | Целевая утилизация, доля в (0; 1] (по умолчанию 0,65) | `Employee.target_utilization` |
| `K_i` | Биллируемая ёмкость, `H_i × u_i` | вычисляется |
| `c_i` | Себестоимость биллируемого часа | вычисляется (`cost_rate`) |
| `ĉ_i` | Себестоимость контрактного часа | вычисляется |
| `b_i` | Ставка для клиента за час | `Employee.billing_rate` |
| `OH` | Накладные фирмы за месяц | `Firm.overheads` |
| `ρ` | Ставка накладных на биллируемый час | вычисляется (`overhead_rate`) |
| `Labor` | Трудозатраты проекта, `Σ c·h` | вычисляется |
| `Own` | Собственные (неперевыставляемые) расходы проекта | `Disbursement`, тип `own` |
| `C` | Издержки проекта, `Labor + ρ·Σh + Own` | вычисляется |
| `R` | Выручка за услуги без НДС | вычисляется по модели цены |
| `v` | Ставка НДС режима | реестр ставок |
| `VAT` | НДС, предъявляемый клиенту | вычисляется |
| `D` | Возмещаемые расходы (пошлины) | `Disbursement`, тип `billable` |
| `t`, `t_min` | Ставка налога режима и ставка минимального налога | реестр ставок |
| `s_i` | Взносы работодателя на биллируемый час, `взносы_i / K_i` | вычисляется |
| `S` | Взносы на часах проекта, `Σ_a s_i(a)·h_a` | вычисляется |
| `κ` | Предел уменьшения налога УСН «доходы» на взносы (50%) | реестр ставок |
| `N` | Вознаграждение из прибыли на часах проекта, `Σ c_i·h_a` по таким сотрудникам | `Employee.paid_from_profit` |
| `Tax` | Налог на доход или прибыль по проекту | вычисляется |
| `NNE`, `m` | Чистая прибыль проекта и маржа NNE | вычисляется |
| `m*` | Целевая маржа NNE | `Project.target_margin` (по умолчанию 0,30) |
| `V_s` | Теневая стоимость этапа | вычисляется |

Деньги внутри ядра — `Decimal` без округления; на выводе — до копейки
(тиына), «половина вверх». Все суммы расчёта приводятся к валюте проекта
(раздел 9).

## 3. Себестоимость (L-01, L-12)

### 3.1. Полная стоимость сотрудника

`W_i` — сколько сотрудник стоит фирме в месяц. Задаётся одним из двух способов:

- **Оклад и взносы**: `W_i = оклад_i × (1 + ставка взносов_i)`. Ставка взносов
  по умолчанию — эффективная ставка, рассчитанная для этого оклада по правилам
  страны трудоустройства (раздел 3.1.1); её можно отредактировать.
- **Сумма в месяц**: `W_i` вводится напрямую. Так задаётся **нормативное
  вознаграждение партнёра** по Майстеру — рыночная цена его труда, если бы
  партнёр был наёмным юристом. Это отделяет оплату труда партнёра от прибыли
  фирмы: NNE остаётся доходом собственника на капитал и риск, а не скрытой
  зарплатой. Так же вводится стоимость подрядчика.

Страна трудоустройства определяется валютой оклада: KZT — РК, остальные
валюты — РФ.

Флаг **«выплачивается из прибыли»** (`Employee.paid_from_profit`) отмечает
сотрудника, чьё вознаграждение фирма на деле выплачивает из прибыли
(дивидендами), а не как зарплату. В себестоимость проекта он входит как обычно,
но для налога «доходы − расходы» его трудозатраты расходом не являются
(раздел 5.1).

#### 3.1.1. Взносы работодателя (L-08)

Взносы считаются помесячно за календарный год при постоянном окладе `S`
(12 выплат), эффективная ставка — годовые взносы / `12·S`. Ставки, базы и
пределы — из реестра, источники — в `rates_verification.md`.

**РФ, общий тариф** (УСН, ОСНО; п. 3 ст. 425 НК РФ). Пусть `B` — единая
предельная база (2026: 2 979 000 ₽), `S_cum` — выплаты с начала года до
текущей:

```
в пределах базы:  part_in  = clamp(B − S_cum, 0, S)
взносы месяца   = 30% × part_in + 15,1% × (S − part_in) + 0,2% × S
```

0,2% — взносы на страхование от несчастных случаев для I класса
профессионального риска; класс зависит от основного ОКВЭД фирмы.

**РФ, пониженный тариф МСП** (ст. 427 НК РФ в редакции 425-ФЗ и 104-ФЗ):
выплаты сверх `1,5 × МРОТ` в месяц облагаются по 15% вне зависимости от
базы, часть до `1,5 × МРОТ` — по общему тарифу:

```
low  = min(S, 1,5 × МРОТ);   high = S − low
part_in = clamp(B − S_cum, 0, low)
взносы месяца = 30% × part_in + 15,1% × (low − part_in) + 15% × high + 0,2% × S
```

С 2026 года тариф МСП доступен только по видам деятельности из перечня
Правительства (распоряжение № 4125-р); входит ли в него деятельность фирмы —
вопрос к юристу.

**РФ, АУСН** — тариф 0% (ст. 18 17-ФЗ), фиксированный взнос на травматизм
платится за организацию в целом и на сотрудника не относится. **НПД** —
сотрудников быть не может (раздел 15). **Нулевой тариф** — для особых
категорий плательщиков из v0.3; основание пользователь проверяет сам.

**РК, общеустановленный режим.** Взносы считаются от месячного дохода `S`, с
пределами в МЗП и МРП текущего года:

```
ОПВ (работника, удерживается)  = 10% × min(S, 50 МЗП)
ВОСМС (работника, удерживается) = 2% × min(S, 20 МЗП)
СО     = 5% × clamp(S − ОПВ, 1 МЗП, 7 МЗП)
ООСМС  = 3% × min(S, 40 МЗП)
ОПВР   = 3,5% × clamp(S, 1 МЗП, 50 МЗП)
соцналог: ТОО — 6% × max(S − ОПВ − ВОСМС, 14 МРП);  ИП — 1 МРП за работника
взносы работодателя = СО + ООСМС + ОПВР + соцналог
```

ОПВ и ВОСМС удерживаются из оклада и в `W` не входят; они нужны только для
баз СО и соцналога. С 2026 года соцналог не уменьшается на СО (новый НК РК).
ОПВР платится за работников 1975 года рождения и младше — модель считает его
за всех.

Если оклад не задан (`S = 0`), карточке показывается номинальная ставка — сумма
ставок без пределов и минимальных баз: РФ 30,2%, РК ТОО
`3% + 5% × 0,9 + 3,5% + 6% × 0,88 = 16,28%`, РК ИП `3% + 4,5% + 3,5% = 11%`.

### 3.2. Себестоимость биллируемого часа

```
K_i = H_i × u_i
c_i = W_i / K_i           — себестоимость биллируемого часа (cost_rate)
ĉ_i = W_i / H_i           — себестоимость контрактного часа
c_i − ĉ_i = c_i × (1 − u_i)   — стоимость недозагрузки на час
```

Клиенту продаётся только биллируемое время. Остальные `1 − u_i` рабочего
времени (обучение, развитие бизнеса, внутренние задачи, простои) фирма всё
равно оплачивает, и возместить их можно только через цену проданных часов.
Поэтому в расчёт проекта идёт `c_i`, а не `ĉ_i`.

В v0.3 калькулятор ФОТ делил `W_i` на контрактные часы, то есть давал `ĉ_i`
(L-01). При утилизации 65% это занижает себестоимость часа в 1/0,65 ≈ 1,54 раза.

Утилизация задаётся по каждому сотруднику: у партнёров она обычно ниже
(управление, привлечение клиентов). Допустимы значения от 0 (не включая) до 1;
переработки моделируются увеличением `H_i`.

На уровне проекта стоимость недозагрузки `Σ_a (c_i − ĉ_i)·h_a` показывается
отдельно: это сумма, которую v0.3 не включал в себестоимость.

### 3.3. Ставка накладных

```
ρ = Σ_k OH_k(мес) / Σ_i K_i
```

- Знаменатель — биллируемая ёмкость **всей фирмы**, сумма `K_i` по команде.
  Отдельного поля «биллируемые часы фирмы» больше нет: ёмкость выводится из
  команды.
- Ежемесячные накладные входят как есть, годовые — 1/12, разовые не входят.
- Накладные в разных валютах приводятся к валюте проекта (раздел 9).
- В команду входят только сотрудники, чьи часы продаются клиентам. Ассистент,
  бухгалтер и другие небиллируемые сотрудники — это накладные.

Теперь числитель и знаменатель согласованы: `c_i` и `ρ` оба считаются на
биллируемый час.

### 3.4. Издержки проекта

```
Labor = Σ_a c_i(a) × h_a
OH_proj = ρ × Σ_a h_a
Own = Σ собственных расходов проекта
C = Labor + OH_proj + Own
```

Собственный расход — тот, что фирма несёт за свой счёт и клиенту не
перевыставляет (курьер, нотариальный перевод, командировка). Категория
«Прочее» из v0.3 — тоже собственный расход: она входит в `Own`, уменьшает NNE
и закладывается в фикс-цену (L-12; в v0.3 такие расходы терялись).

## 4. Выручка, НДС и возмещаемые расходы (L-02)

### 4.1. Выручка

`R` — выручка за услуги **без НДС**. Только она — доход фирмы. Как получается
`R`, определяет модель цены (раздел 7).

У проекта есть режим ввода цен (`Project.vat_mode`), он относится к ставкам
для клиента, потолку и согласованной фикс-цене:

- **без НДС** (по умолчанию): введённые цены — это `R`, НДС начисляется сверху;
- **включая НДС**: введённая цена `P` уже содержит НДС, `R = P / (1 + v)`.

Цена «издержки + маржа» всегда вычисляется как `R`: от неё считаются маржа и
налог. Клиенту она показывается без НДС и с НДС.

### 4.2. НДС

```
VAT = v × R
```

НДС фирма получает от клиента и перечисляет в бюджет. Это не её доход и не её
расход: NNE от НДС не зависит, в фикс-цену НДС не закладывается. В v0.3 НДС
вычитался из NNE и закладывался в фикс-цену как налог фирмы (L-02).

Если режим без НДС (`v = 0`), то `VAT = 0`.

### 4.3. Возмещаемые расходы

`D` — пошлины Роспатента и Казпатента и другие расходы, которые фирма платит
за клиента и перевыставляет ему. Это транзит:

- не входят в `R` и не влияют на маржу;
- не облагаются налогом на доход и НДС;
- в смете и КП — отдельная строка «Возмещаемые расходы».

```
К оплате клиентом = R + VAT + D
```

## 5. Налог на доход или прибыль

### 5.1. Две базы

```
«доходы»:            Tax = max( t × R − S,  (1 − κ) × t × R )
«доходы − расходы»:  Tax = max( t × max(R − C + N, 0), t_min × R )
```

| Режим | База | `t` | `t_min` | `κ` | НДС `v` |
|---|---|---|---|---|---|
| УСН «доходы» | доходы | 6% | — | 50% | 0 / 5% / 7% |
| УСН «доходы − расходы» | доходы − расходы | 15% | 1% | — | 0 / 5% / 7% |
| АУСН «доходы» | доходы | 8% | — | — | 0 |
| НПД | доходы | 4% (физлица) / 6% (юрлица) | — | — | 0 |
| ОСНО | доходы − расходы | 25% | — | — | 22% |
| ОУР РК, ТОО (КПН) | доходы − расходы | 20% | — | — | 0 / 16% |
| ОУР РК, ИП (ИПН) | доходы − расходы | 10% | — | — | 0 / 16% |

`t_min` — минимальный налог УСН «доходы − расходы»: 1% доходов (п. 6
ст. 346.18 НК РФ). В v0.3 его не было (L-08). Для режимов без минимального
налога `t_min = 0`.

**Уменьшение УСН «доходы» на взносы** (п. 3.1 ст. 346.21 НК РФ). Организация
или ИП с работниками уменьшает налог на уплаченные страховые взносы, но не
более чем на `κ = 50%`. На уровне проекта взносы относятся на часы так же, как
себестоимость:

```
s_i = взносы_i(мес) / K_i              взносы на биллируемый час
S   = Σ_a s_i(a) × h_a
```

В `S` входят только сотрудники с окладом и взносами (`Salary`), трудоустроенные
в стране расчёта налога. У «суммы в месяц» взносы не выделены, поэтому `S` от
неё не растёт — налог остаётся оценкой сверху. Для остальных режимов `κ = 0`:
на базе «доходы − расходы» взносы уже входят в `C`.

**Вознаграждение из прибыли.** `N = Σ_a c_i(a) × h_a` по сотрудникам с флагом
«выплачивается из прибыли» (раздел 3.1). Оно входит в `C` и уменьшает NNE, но
не уменьшает базу налога «доходы − расходы». Накладные, отнесённые на часы
такого сотрудника, остаются расходом. На базе «доходы» `N` не влияет на налог.
По умолчанию флаг выключен, `N = 0` и `S` касается только сотрудников с
окладом, поэтому цифры фазы 2 не меняются.

Налоговая база — выручка без НДС: и УСН, и налог на прибыль, и КПН считаются
от доходов без предъявленного покупателю НДС. Возмещаемые расходы `D` в базу
не входят.

### 5.2. Налог проекта — аппроксимация

Налог платится за год по фирме целиком, а не по проекту. `Tax` — это доля
годового налога, которую можно отнести на проект, если проект типичен для
фирмы. Отсюда ограничения:

- минимальный налог сравнивается с налогом на прибыль по проекту, а не по году;
- убыток проекта не создаёт «отрицательного налога» на уровне проекта
  (`max(R − C + N, 0)`), хотя в годовом расчёте он уменьшил бы налог по другим
  проектам;
- издержки `C`, кроме вознаграждения из прибыли `N`, считаются признаваемыми
  расходами (раздел 14);
- предел уменьшения на взносы `κ` применяется к налогу проекта, а не к
  годовому налогу; взносы считаются начисленными за те же часы, а не
  уплаченными в периоде.

## 6. NNE, маржа и показатели (L-15)

```
NNE = R − C − Tax
m = NNE / R                        (при R = 0 маржа не определена и показывается как 0)
эффективная ставка налога = Tax / R
стоимость недозагрузки = Σ_a (c_i − ĉ_i) × h_a
средневзвешенная ставка (blended rate) = Σ_a b_i·h_a / Σ_a h_a
рычаг (leverage) = часы младших (младший юрист, стажёр) / часы старших (партнёр, старший юрист)
```

Все относительные показатели проекта считаются от одной базы — `R`. В v0.3
эффективная ставка налога делилась на услуги + пошлины, а маржа — на услуги
(L-15).

## 7. Модели ценообразования (L-03)

### 7.1. Почасовая

```
R = Σ_a b_i(a) × h_a               (÷ (1 + v), если ставки «включая НДС»)
```

### 7.2. Почасовая с потолком (capped fee)

```
R = min(Σ_a b_i(a) × h_a, cap)
списание = Σ_a b_i(a) × h_a − R
```

`cap` указывается в том же режиме НДС, что и ставки.

### 7.3. Фиксированная цена «издержки + маржа»

Задана целевая маржа `m*`. Ищется наименьшая выручка `P = R`, при которой
`NNE = m* × P`.

**База «доходы».** Без взносов к уменьшению (`S = 0` или `κ = 0`):
`P − C − tP = m*P`, откуда

```
P = C / (1 − m* − t)
```

С уменьшением на взносы налог — `max(tP − S, (1 − κ)tP)`, и
`NNE(P) = min( (1 − t)P − C + S, (1 − (1 − κ)t)P − C ) − m*P`. Обе ветви растут
с `P`, поэтому

```
P = max( (C − S) / (1 − t − m*),  C / (1 − (1 − κ)t − m*) )
```

При `S = 0` первая ветвь не меньше второй, и формула совпадает с предыдущей.
`S ≤ C` всегда: взносы — часть трудозатрат. Если режим не уменьшает налог на
взносы (`κ = 0`: АУСН, НПД), вторая ветвь равна `C / (1 − t − m*)` и не меньше
первой: взносы цену не снижают (до фазы 7 ядро в этом случае вычитало `S`, L-23).

**База «доходы − расходы» без минимального налога** (при `P ≥ C − N`):
`P − C − t(P − C + N) = m*P`, откуда

```
P_A = (C(1 − t) + tN) / (1 − t − m*)
```

При `N = 0` это `C(1 − t) / (1 − t − m*)`. Условие `P_A ≥ C − N` выполняется
всегда: `P_A − (C − N) = (m*C + (1 − m*)N) / (1 − t − m*) ≥ 0`.

**С минимальным налогом.** Если работает минимальный налог,
`P − C − t_min·P = m*P`, откуда

```
P_B = C / (1 − t_min − m*)
```

`NNE(P) = min( (1 − t)P − (1 − t)C − tN, (1 − t_min)P − C ) − m*P`. Обе ветви
растут с `P`, поэтому `NNE ≥ m*P` ровно тогда, когда `P ≥ P_A` и `P ≥ P_B`.
Наименьшая такая цена:

```
P = max(P_A, P_B)
```

Отдельная проверка применимости не нужна: при `P = max(P_A, P_B)` автоматически
работает та ветвь налога, решением которой является `P`. Минимальный налог
определяет цену при низкой целевой марже: для УСН 15% / 1% — при
`m* < 0,0085 / 0,15 ≈ 5,7%` (в том числе для цены безубыточности `m* = 0`).

**Когда цели не достичь.** Нужны положительные знаменатели: `1 − m* − t > 0`
(и `1 − t_min − m* > 0` для минимального налога). Знаменатель
`1 − (1 − κ)t − m*` не меньше `1 − t − m*` и отдельно не проверяется. Иначе ядро бросает
`FixedPriceError` с текстом «Целевая маржа m* недостижима при режиме X:
маржа + ставка налога = … ≥ 100%». При `C = 0` цена равна 0.

В v0.3 цена искалась итерациями, а НДС входил в знаменатель как налог фирмы:
`C / (1 − m* − t − v)` (L-02, L-03). Итерации совпадали с закрытыми формулами
до копейки, так что цифры меняет только уход `v` из знаменателя.

### 7.4. Согласованная фиксированная цена

Цена уже согласована с клиентом (`FixedPricing.price`): `R = price`
(или `price / (1 + v)` в режиме «включая НДС»), а `NNE` и `m` — следствие.
Так считается слайд 3 (раздел 12), так же считаются точка безубыточности при
зафиксированной цене (раздел 16) и план–факт (раздел 18). `m*` здесь — только
порог светофора.

## 8. Этапы и светофор (L-04, L-05, L-19)

### 8.1. Назначения

Этап — это набор назначений «сотрудник × часы». Пирамида «партнёр проверяет
2 ч, юрист делает 8 ч» — один этап с двумя назначениями. В v0.3 на этапе был
один исполнитель, и пирамиду приходилось задавать одноимёнными этапами (L-05).
Названия этапов в проекте уникальны.

### 8.2. Выручка этапа — по теневой стоимости

```
V_s = Σ_{a∈s} b_i(a) × h_a
R_s = R × V_s / Σ_s V_s
```

Теневая стоимость — сколько этап стоил бы клиенту по ставкам. Час партнёра
весит больше часа стажёра; деление по часам (v0.3) переносило выручку с
партнёрских этапов на стажёрские, и светофор показывал проблему не там (L-04).

Если ставки для клиента не заданы ни у кого (`Σ V_s = 0`, чистый «издержки +
маржа»), ключом служат трудозатраты `Labor_s`, а если и их нет — часы `H_s`.

В почасовой модели со ставками без НДС `R_s = V_s`, с потолком — доля `cap`
по теневой стоимости.

### 8.3. Издержки этапа

```
C_s = Labor_s + ρ × H_s + Own_s
```

Собственный расход можно привязать к этапу (`Disbursement.stage`). Расходы без
привязки распределяются по тому же ключу, что и выручка (`V_s / Σ V`).
В v0.3 собственные расходы этапам не доставались вовсе (L-04).

### 8.4. Налог этапа

Распределение повторяет логику налога проекта, и `Σ_s Tax_s = Tax` всегда:

- база «доходы», предел `κ` не достигнут: `Tax_s = t × R_s − S_s`, где
  `S_s = Σ_{a∈s} s_i(a)·h_a` — взносы на часах этапа (без взносов —
  `t × R_s`);
- база «доходы − расходы», налог проекта равен налогу на прибыль
  `t(R − C + N) > 0`: `Tax_s = t × (R_s − C_s + N_s)`. Убыточный этап получает
  отрицательный налог: он уменьшает налог по проекту;
- иначе (работает предел `κ`, минимальный налог или налог нулевой):
  `Tax_s = Tax × R_s / R`.

### 8.5. Маржа этапа и светофор

```
m_s = (R_s − C_s − Tax_s) / R_s        (при R_s = 0 — 0)
```

| Цвет | Условие |
|---|---|
| green | `m_s ≥ m*` |
| yellow | `0 < m_s < m*` |
| red | `m_s ≤ 0` |

Пороги — именованные константы ядра; маржа сравнивается с ними с точностью
0,0001 п. п., чтобы погрешность деления в `Decimal` (порядка 10⁻²⁸) не
перекрашивала этап с маржой, ровно равной цели. Маржа этапа считается **после** налога и
сравнивается с целевой маржой после налога (в v0.3 сравнивалась маржа до
налога, L-04). Светофор работает для всех моделей цены; в почасовой `m*` — порог
сравнения, цену он не определяет. Строки этапов на дашборде показывают `m_s`,
а не `(ставка − себестоимость) / ставка` (L-19).

## 9. Валюты (L-06)

- Валюта проекта — валюта страны расчёта налога: RUB для РФ, KZT для РК. В
  режиме «Оба» страну выбирают на проекте.
- У каждой денежной величины на входе своя валюта: у оклада и ставок сотрудника,
  у накладных, у расходов проекта.
- Курсы задаются как цена единицы валюты в рублях (`₽ за 1 ₸`, `₽ за 1 $`), так
  их публикует ЦБ РФ. Пересчёт:

```
amount_target = amount_source × rub_per(source) / rub_per(target),   rub_per(RUB) = 1
```

- Все входы приводятся к валюте проекта **до** расчёта: `W_i`, `b_i`, `OH`,
  `Own`, `D`. Ставка накладных `ρ` считается в валюте проекта.
- Если нужен курс, которого нет, ядро бросает понятную ошибку («Укажите курс
  ₽ за 1 ₸»), а не складывает суммы как есть.

### 9.1. Откуда берутся курсы

Курсы можно загрузить на дату (`fx.fetch_rates`) или ввести вручную:

- **ЦБ РФ** (основной источник, `XML_daily.asp`): официальный курс в рублях за
  `Nominal` единиц валюты; `₽ за 1 ₸ = Value / Nominal` для KZT (номинал 100),
  `₽ за 1 $ = Value / Nominal` для USD.
- **НБРК** (запасной источник, `get_rates.cfm`): курс в тенге за `quant` единиц;
  `₽ за 1 ₸ = 1 / (₸ за 1 ₽)`, `₽ за 1 $ = (₸ за 1 $) / (₸ за 1 ₽)`.
- **Вручную** — если сервис недоступен или пользователь хочет свой курс.

Загруженные курсы хранятся в памяти процесса (по источнику и дате), на диск
ничего не пишется. Курсы на прошедшую дату не меняются и кэшируются до конца
процесса, на сегодня — 6 часов (`fx.TODAY_CACHE_TTL`). Если ЦБ РФ недоступен,
используется НБРК; если недоступны оба — ошибка с предложением ввести курс
вручную, введённые курсы остаются как были.

**Пример.** Фирма в режиме «Оба», проект считается по РФ, курс 0,18 ₽ за 1 ₸
(условный). Аренда в Москве 120 000 ₽ и в Алматы 300 000 ₸ в месяц дают
накладные `120 000 + 300 000 × 0,18 = 174 000 ₽`; v0.3 складывал их в
420 000 «рублей». Пошлины Роспатента 38 500 ₽ и Казпатента 120 000 ₸ дают
`D = 38 500 + 21 600 = 60 100 ₽`, а не 158 500.

## 10. Пример 1. Почасовая модель

### 10.1. Фирма

Команда — три человека с параметрами слайда 3 (себестоимость часа 4 000 /
1 500 / 500 ₽). Для круглых чисел у всех `H = 160` ч и `u = 62,5%`, то есть
`K = 100` ч в месяц.

| Сотрудник | Роль | `W`, ₽/мес | `ĉ = W/H`, ₽/ч | `c = W/K`, ₽/ч | Недозагрузка, ₽/ч | `b`, ₽/ч |
|---|---|---|---|---|---|---|
| Партнёр | партнёр | 400 000 (нормативное вознаграждение) | 2 500 | 4 000 | 1 500 | 10 000 |
| Юрист | младший юрист | 150 000 (оклад + взносы) | 937,5 | 1 500 | 562,5 | 5 000 |
| Стажёр | стажёр | 50 000 | 312,5 | 500 | 187,5 | 2 000 |

Накладные 30 000 ₽ в месяц, ёмкость фирмы `3 × 100 = 300` ч:
`ρ = 30 000 / 300 = 100 ₽/ч`.

### 10.2. Проект «Регистрация товарного знака»

| Этап | Назначения | `H_s`, ч | `Labor_s`, ₽ | `V_s`, ₽ |
|---|---|---|---|---|

| 2. Подготовка и подача заявки | Юрист 4 ч, Стажёр 10 ч | 14 | 4·1 500 + 10·500 = 11 000 | 4·5 000 + 10·2 000 = 40 000 |
| Итого | | 24 | 31 000 | 100 000 |

Расходы проекта:

- пошлина за подачу заявки (условно) 15 000 ₽ — возмещаемый расход `D`;
- нотариальный перевод доверенности 1 800 ₽ — собственный расход этапа 2.

Издержки:

```
Labor   = 31 000
OH_proj = 100 × 24 = 2 400
Own     = 1 800
C       = 35 200 ₽
```

Стоимость недозагрузки `= 2·1 500 + 12·562,5 + 10·187,5 = 11 625 ₽`: на столько

Средневзвешенная ставка `100 000 / 24 = 4 166,67 ₽/ч`, рычаг `(12 + 10) / 2 = 11`.

### 10.3. Выручка и оплата

Ставки без НДС: `R = ΣV = 100 000 ₽`. В обоих режимах ниже НДС 5%:

```
VAT = 0,05 × 100 000 = 5 000
К оплате = 100 000 + 5 000 + 15 000 = 120 000 ₽
```

(Если бы ставки были «включая НДС»: `R = 100 000 / 1,05 = 95 238,10`,

## 11. Пример 2. Фиксированная цена

Тот же проект и фирма (`C = 35 200 ₽`, `D = 15 000 ₽`), целевая маржа
`m* = 30%`.

### 11.1. База «доходы»: УСН 6% + НДС 5%

```
P = C / (1 − m* − t) = 35 200 / (1 − 0,30 − 0,06) = 35 200 / 0,64 = 55 000 ₽
Tax = 0,06 × 55 000 = 3 300
NNE = 55 000 − 35 200 − 3 300 = 16 500 = 30% × 55 000   ✓
VAT = 0,05 × 55 000 = 2 750
К оплате = 55 000 + 2 750 + 15 000 = 72 750 ₽
```

### 11.2. База «доходы − расходы»: УСН 15% (мин. 1%) + НДС 5%

```
P_A = C(1 − t) / (1 − t − m*) = 35 200 × 0,85 / 0,55 = 54 400
P_B = C / (1 − t_min − m*)    = 35 200 / 0,69        = 51 014,49
P = max(P_A, P_B) = 54 400 ₽
Tax = max(0,15 × (54 400 − 35 200); 0,01 × 54 400) = max(2 880; 544) = 2 880
NNE = 54 400 − 35 200 − 2 880 = 16 320 = 30% × 54 400   ✓
VAT = 2 720;  к оплате = 54 400 + 2 720 + 15 000 = 72 120 ₽
```

### 11.3. Когда цену определяет минимальный налог

Цена безубыточности (`m* = 0`) на УСН 15%:

```
P_A = 35 200 × 0,85 / 0,85 = 35 200
P_B = 35 200 / 0,99        = 35 555,56
P = 35 555,56 ₽;  Tax = 0,01 × 35 555,56 = 355,56 (налог на прибыль был бы 53,33);  NNE = 0
```

Безубыточная цена выше издержек на 1/99: даже без прибыли фирма платит
минимальный налог. Для сравнения, на УСН 6% цена безубыточности
`35 200 / 0,94 = 37 446,81 ₽`.

Цель недостижима при `m* ≥ 1 − t`: на УСН 6% — от 94%, на УСН 15% — от 85%.

### 11.4. Этапы

Выручка этапов делится по теневой стоимости 60 000 : 40 000.

| Этап | `C_s` | УСН 6%: `R_s` / `Tax_s` / NNE / `m_s` | УСН 15%: `R_s` / `Tax_s` / NNE / `m_s` |
|---|---|---|---|
| 1 | 21 000 | 33 000 / 1 980 / 10 020 / 30,36% 🟢 | 32 640 / 1 746 / 9 894 / 30,31% 🟢 |
| 2 | 14 200 | 22 000 / 1 320 / 6 480 / 29,45% 🟡 | 21 760 / 1 134 / 6 426 / 29,53% 🟡 |
| Σ | 35 200 | 55 000 / 3 300 / 16 500 | 54 400 / 2 880 / 16 320 |

Этап 2 чуть ниже цели: на него отнесён нотариальный перевод (1 800 ₽).

Если поделить ту же цену 55 000 ₽ по часам, как v0.3 (10 : 14), и сравнить
маржу до налога без собственных расходов, цвета поменяются местами: этап 1 —
`R = 22 916,67`, маржа 8,36% 🟡; этап 2 — `R = 32 083,33`, маржа 61,35% 🟢.
Партнёрский этап выглядел бы проблемным, хотя проблемы в нём нет.

### 11.5. Тот же проект в v0.3

v0.3 считал бы себестоимость часа от контрактных часов (2 500 / 937,5 /
312,5 ₽): `Labor = 19 375`, `C = 23 575 ₽` (при тех же 300 биллируемых часах
фирмы). Цена на УСН 6% + НДС 5%:

| Шаг | Формула | Цена, ₽ |
|---|---|---|
| v0.3 | `23 575 / (1 − 0,30 − 0,06 − 0,05)` | 39 957,63 |
| НДС не закладывается в цену (L-02) | `23 575 / 0,64` | 36 835,94 |
| Себестоимость биллируемого часа (L-01) | `35 200 / 0,64` | **55 000,00** |

Фирма продала бы проект на 27% дешевле его себестоимости с целевой маржой, а
клиент заплатил бы НДС, который фирма уже «оплатила» из своей цены.

### 11.6. Взносы и вознаграждение из прибыли (фаза 3)

Тот же проект (`R = 100 000 ₽` в почасовой модели, `C = 35 200 ₽`, `m* = 30%`).

**УСН «доходы» 6%, уменьшение на взносы.** Пусть `W` юриста 150 000 ₽ — это
оклад 120 000 ₽ и взносы 30 000 ₽ (ставка 25% — для круглых чисел). Тогда
`s = 30 000 / 100 = 300 ₽/ч`, а у юриста на проекте 12 ч: `S = 3 600 ₽`.
Себестоимость часа не меняется (1 500 ₽), меняется только налог:

```
Tax = max(0,06 × 100 000 − 3 600;  0,5 × 0,06 × 100 000) = max(2 400; 3 000) = 3 000
NNE = 100 000 − 35 200 − 3 000 = 61 800 (61,80%; без уменьшения — 58 800)
```

Работает предел 50%, поэтому налог этапов делится по выручке: 1 800 и 1 200 ₽.
Фикс-цена:

```
P = max( (35 200 − 3 600) / 0,64;  35 200 / (1 − 0,03 − 0,30) )
  = max(49 375;  52 537,31) = 52 537,31 ₽
Tax = 0,03 × 52 537,31 = 1 576,12;   NNE = 15 761,19 = 30% × P   ✓
```

**УСН «доходы − расходы» 15%, партнёр получает вознаграждение из прибыли.**
Партнёр на проекте 2 ч по 4 000 ₽: `N = 8 000 ₽`. В почасовой модели

```
Tax = max(0,15 × (100 000 − 35 200 + 8 000);  1 000) = 10 920
NNE = 100 000 − 35 200 − 10 920 = 53 880 (без флага — 55 080)
```

Фикс-цена:

```
P_A = (35 200 × 0,85 + 0,15 × 8 000) / 0,55 = 31 120 / 0,55 = 56 581,82
P_B = 35 200 / 0,69 = 51 014,49
P = 56 581,82 ₽;  Tax = 0,15 × 29 381,82 = 4 407,27;  NNE = 16 974,55 = 30% × P   ✓
```

Налог этапов: `Tax_s = 0,15 × (R_s − C_s + N_s)`, у этапа 1 `N_1 = 8 000`, у
этапа 2 `N_2 = 0`.

## 14. Допущения и ограничения

- **Налог проекта — аппроксимация** годового налога (раздел 5.2).
- **Издержки признаются расходами** для базы «доходы − расходы», кроме
  вознаграждения сотрудников с флагом «выплачивается из прибыли» (раздел 5.1).
  Если флаг не поставлен, а вознаграждение на деле выплачивается дивидендами,
  налог по проекту занижен.
- **Уменьшение налога УСН «доходы» на страховые взносы** моделируется на уровне
  проекта (раздел 5.1): учитываются только взносы сотрудников с окладом.
  Взносы ИП «за себя» и больничные за счёт работодателя не учитываются, предел
  50% применяется ко всем (ИП без работников уменьшает налог без предела, но
  без работников с окладом и `S = 0`).
- **Входящий НДС** не моделируется: накладные и собственные расходы вводятся
  в сумме, которую фирма фактически несёт.
- **Пошлины — по агентской схеме.** Если фирма перевыставляет их как часть
  цены услуги, а не как возмещение, они могут войти в доход и базу НДС; модель
  этот случай не покрывает.
- **Разовые накладные** не распределяются по проектам.
- **Взносы** считаются при постоянном окладе 12 месяцев; премии, отпускные и
  неполный год не моделируются. Ставка в карточке — эффективная за год, в `W`
  она входит как доля оклада.
- **ИПН ИП в РК** — 10%; ставка 15% с дохода сверх 230 000 МРП в год не
  моделируется (валидатор предупреждает, раздел 15). **НДФЛ и ИПН работника**
  удерживаются из оклада и в `W` не входят: оклад вводится до удержаний.
- **Ставки — 2026 года** (реестр `rates/*_2026.yaml`). Часть ставок и пошлин
  не удалось сверить с полным текстом первоисточника; они помечены
  `needs_review` и перечислены в `rates_verification.md`.
- **Округление.** Внутри расчёта округления нет. В документах для клиента
  строка «К оплате» должна быть суммой уже округлённых строк (фаза 7), иначе
  возможно расхождение в 1 коп. Итог «рентабелен / безубыточен / убыточен»
  определяется по NNE, округлённому до копейки: цена безубыточности,
  найденная делением, даёт NNE порядка ±10⁻²⁴.

## 16. Точка безубыточности по часам

Код — `rentab_core.analysis.sensitivity.break_even`, golden-тесты —
`tests/core/test_sensitivity.py`.

### 16.1. Вопрос

Цена проекта зафиксирована. Сколько часов сверх плана фирма может потратить,
прежде чем NNE станет нулём? Часы добираются одним из двух способов
(направление `d`):

- **микс проекта** — все назначения растут в одной пропорции:
  `h_a(x) = h_a × (1 + x / H)`, где `H = Σ_a h_a`;
- **исполнитель `i`** — растут только его часы, на любом этапе: NNE проекта
  от этапа не зависит. Исполнителем может быть и сотрудник, которого в плане
  нет. Если в одной роли несколько сотрудников, у каждого своя строка:
  себестоимость часа у них разная.

### 16.2. Параметры дополнительного часа

| | Микс проекта | Исполнитель `i` |
|---|---|---|
| `h_d` — часы в плане | `H` | `Σ_{a: i(a) = i} h_a` |
| `k_d` — себестоимость часа с накладными | `Labor / H + ρ` | `c_i + ρ` |
| `b_d` — ставка для клиента без НДС | `V / H` (средневзвешенная ставка) | `b_i` |
| `s_d` — взносы на час (раздел 5.1) | `S / H` | `s_i` |
| `n_d` — вознаграждение из прибыли на час | `N / H` | `c_i` с флагом «из прибыли», иначе 0 |

Ставки и потолок «включая НДС» делятся на `1 + v`. При `x` дополнительных
часах

```
C(x) = C + k_d·x      S(x) = S + s_d·x      N(x) = N + n_d·x      V(x) = V + b_d·x
```

Собственные расходы `Own` и возмещаемые `D` от часов не зависят. Ставка
накладных `ρ` — величина фирмы (раздел 3.3): от часов проекта она не зависит.

### 16.3. Что значит «цена зафиксирована»

| Модель | Выручка `R(x)` | |
|---|---|---|
| Согласованная фикс-цена | `R` | цена не меняется |
| Фикс «издержки + маржа» | `P` плана | цена держится: она уже предложена клиенту (16.6) |
| С потолком | `min(V + b_d·x, cap)` | часы оплачиваются, пока выручка не упрётся в потолок |
| Почасовая | `V + b_d·x` | каждый час оплачивается, зафиксированной цены нет (16.5) |

### 16.4. NNE как функция часов

Налог — максимум двух ветвей (раздел 5.1), выручка с потолком — минимум двух.
Поэтому NNE — минимум нескольких линейных функций от `x`:

```
«доходы»:            NNE(x) = min( (1 − t)·R − C + S,   (1 − (1 − κ)t)·R − C )
«доходы − расходы»:  NNE(x) = min( (1 − t)·(R − C) − t·N,   (1 − t_min)·R − C )
```

(всё — функции `x`). При `κ = 0` у базы «доходы» одна ветвь `(1 − t)R − C`.
Формула базы «доходы − расходы» верна и при убытке: налог на прибыль тогда 0,
и вторая ветвь (минимальный налог или нулевой налог при `t_min = 0`) не больше
первой.

Подставим `R(x) = R₀ + ϱ·x`: в фиксе `R₀ = R`, `ϱ = 0`; в почасовой
`R₀ = V`, `ϱ = b_d`; с потолком — две части, `(V, b_d)` и `(cap, 0)`, и каждая
ветвь налога даёт по две линии. Получается набор линий `α_j − β_j·x`:

| Ветвь | `α_j` | `β_j` |
|---|---|---|
| «доходы», налог за вычетом взносов | `(1 − t)R₀ − C + S` | `k − s − (1 − t)ϱ` |
| «доходы», предел уменьшения `κ` | `(1 − (1 − κ)t)R₀ − C` | `k − (1 − (1 − κ)t)ϱ` |
| «доходы − расходы», налог на прибыль | `(1 − t)(R₀ − C) − t·N` | `(1 − t)(k − ϱ) + t·n` |
| «доходы − расходы», минимальный налог | `(1 − t_min)R₀ − C` | `k − (1 − t_min)ϱ` |

(`k`, `s`, `n` — параметры направления `d`; `C`, `S`, `N` — значения плана.)

### 16.5. Точка и как её читать

```
NNE(x) ≥ 0  ⇔  α_j − β_j·x ≥ 0 для каждой линии j
x* = min{ α_j / β_j : β_j > 0 }      запас часов
x_* = max{ α_j / β_j : β_j < 0 }     нижняя граница (бывает только у оплачиваемых часов)
```

Часы не бывают отрицательными: `x ≥ −h_d`.

| Итог | Условие | Что говорит интерфейс |
|---|---|---|
| Запас | `NNE ≥ 0`, `x*` есть | «можно потратить ещё `x*` ч (+…% к плану)»; какая ветвь налога работает в точке |
| Не наступает | `NNE ≥ 0`, линий с `β_j > 0` нет | «каждый оплачиваемый час добавляет … ₽ NNE: перерасход оплачивает клиент» |
| Убыток | `NNE < 0`, ноль достижим при `x ≥ −h_d` | «в ноль — если часов на `|x*|` меньше» (или, если часы прибыльны, «на `x_*` больше») |
| Убыток при любых часах | ноль недостижим | «даже без этих часов проект убыточен: дело не в часах» |
| Нет часов | `H = 0` (микс) | «в проекте нет часов» |

Прибыль дополнительного часа — наклон NNE в точке плана: `−β` линии, на которой
лежит NNE плана.

**Почасовая модель.** Если час окупает себестоимость, накладные и налог
(на базе «доходы»: `(1 − t)·b_i > c_i + ρ`), точка не наступает: каждый час
сверх плана увеличивает NNE. Если ставка ниже, каждый час увеличивает убыток,
и точка есть. Интерфейс дополнительно показывает вариант «часы сверх плана не
выставляются» — это фикс с `R = V` плана: часы сверх плана списываются.

### 16.6. Фикс «издержки + маржа»: цена держится

Если пересчитывать цену при каждом изменении часов, то
`P(x) = C(x) / (1 − m* − t)` и `NNE = m*·P(x)` растёт вместе с часами: точки
безубыточности нет, вопрос теряет смысл. Поэтому цена плана держится: она уже
предложена клиенту. Пересчитанную цену показывает «что если» (раздел 17.4).

Пример 2 (раздел 11.1, `P = 55 000`, `NNE = 16 500`, УСН 6%): партнёр —
`16 500 / 4 100 = 4,02 ч`, микс — `16 500 / 1 391,67 = 11,86 ч`.

### 16.7. Слайд 3

`R = 300 000` (согласована), `C = 52 500 + 4 000 = 56 500`, налог
`0,06 × 300 000 = 18 000` от часов не зависит (`S = 0`), `NNE = 225 500`.
Линия одна: `α = 225 500`, `β = k_d`.

| Чем добираются часы | `k_d`, ₽/ч | Запас `x*`, ч | К плану | Часов в точке |
|---|---|---|---|---|
| Микс проекта (5 / 15 / 20) | `52 500 / 40 + 100 = 1 412,50` | 159,65 | +399,1% | 199,65 |
| Партнёр | `4 000 + 100 = 4 100` | **55,00** | +1 100% | 60 |
| Юрист | 1 600 | 140,94 | +939,6% | 155,94 |
| Стажёр | 600 | 375,83 | +1 879,2% | 395,83 |

Партнёр может потратить ещё 55 ч — 60 ч вместо 5. По факту он потратил 62 ч
(+57), а стажёр — на 10 ч меньше плана:
`225 500 − 57 × 4 100 + 10 × 600 = −2 200 ₽`. Это NNE факта (раздел 18.5).

### 16.8. Пример 1

**Почасовая модель, УСН 6% + НДС 5%.** Точка не наступает: каждый оплаченный
час добавляет к NNE партнёр `0,94 × 10 000 − 4 100 = 5 300 ₽`, юрист
`0,94 × 5 000 − 1 600 = 3 100 ₽`, стажёр `0,94 × 2 000 − 600 = 1 280 ₽`, микс
`0,94 × 4 166,67 − 1 391,67 = 2 525 ₽`.

**Если часы сверх плана не выставляются** (выручка остаётся 100 000 ₽):

| | `k_d`, ₽/ч | УСН 6%: `x*`, ч | УСН 15% (мин. налог 1%): `x*`, ч |
|---|---|---|---|
| Микс | 1 391,67 | 42,25 | 45,84 |
| Партнёр | 4 100 | 14,34 | 15,56 |
| Юрист | 1 600 | 36,75 | 39,88 |
| Стажёр | 600 | 98,00 | 106,33 |

На УСН 6% линия одна: `x* = 58 800 / k_d`. На УСН 15% две: налог на прибыль
(`α = 0,85 × 64 800`, `β = 0,85·k_d`, корень `64 800 / k_d`) и минимальный
налог (`α = 0,99 × 100 000 − 35 200 = 63 800`, `β = k_d`, корень
`63 800 / k_d`). Раньше упирается минимальный налог: в точке прибыль до налога
1 000 ₽, налог на прибыль был бы 150 ₽, минимальный налог — 1 000 ₽. Без
минимального налога запас партнёра был бы `64 800 / 4 100 = 15,80 ч`.

**С потолком 120 000 ₽** (УСН 6%, `V = 100 000`). Первые 2 ч партнёра
оплачиваются, пока теневая стоимость не дойдёт до потолка, и NNE растёт до
69 400. Дальше каждый час стоит фирме 4 100 ₽. Линия с потолком:
`α = 0,94 × 120 000 − 35 200 = 77 600`, `β = 4 100`, `x* = 18,93 ч`; линия без
потолка (`β = 4 100 − 9 400 < 0`) точку не ограничивает. С потолком 90 000 ₽
(раздел 10.6) потолок уже сработал: `x* = 49 400 / 4 100 = 12,05 ч`.

### 16.9. Ограничения

- Дополнительные часы помещаются в ёмкость команды: выручка, которую эти часы
  могли бы принести на других проектах, не учитывается.
- Ставка накладных, себестоимость часа и ставки для клиента — как в плане.

## 17. Торнадо и «что если»

Код — `rentab_core.analysis.sensitivity` (`tornado`, `what_if`), тесты —
`tests/core/test_sensitivity.py`.

### 17.1. Факторы

| Фактор | Что умножается на `1 ± X` | Через что влияет на NNE |
|---|---|---|
| Часы | все `h_a` | `Labor`, `ρ·H`, `V` |
| Ставки для клиента | все `b_i` | `R` в почасовой модели и с потолком; в фиксе — только распределение выручки по этапам |
| Утилизация | все `u_i`, не выше 1 | `c_i = W_i / (H_i·u_i)` и `ρ = ΣOH / Σ H_i·u_i` |
| Накладные | все `OH` | `ρ` |
| Курс валюты F | цена F в валюте проекта | все суммы в F: `W`, `b`, `OH`, `Own` |

```
ΔNNE_f(±X) = NNE(f × (1 ± X)) − NNE
```

- Цена — по правилу раздела 16.3: согласованная цена и потолок — как в
  проекте, «издержки + маржа» держится на цене плана, почасовая выручка
  пересчитывается.
- Факторы сортируются по `max(|ΔNNE(−X)|, |ΔNNE(+X)|)`.
- Утилизация стоит в знаменателе, поэтому влияние несимметрично: +10% дают
  `× 1 / 1,1`, −10% дают `× 1 / 0,9`. Утилизация выше 100% не бывает:
  значение упирается в 1, и интерфейс об этом говорит.
- Курс валюты F к валюте проекта P — `q = rub_per(F) / rub_per(P)` (раздел 9);
  он умножается на `1 ± X`, курсы остальных валют к P не меняются. Если
  F ≠ ₽, умножается `rub_per(F)`; если F = ₽ (проект в тенге), все остальные
  курсы делятся на `1 ± X`.
- Фактор «курс» есть только у валют, в которых заданы суммы проекта: оклады
  и ставки исполнителей, накладные, расходы проекта. Пошлины в другой валюте
  меняют «к оплате», но не NNE.

### 17.2. Слайд 3, X = 10%

| Фактор | −10%: NNE (Δ) | +10%: NNE (Δ) |
|---|---|---|
| Утилизация | 219 222,22 (−6 277,78) | 230 636,36 (+5 136,36) |
| Часы | 231 150 (+5 650) | 219 850 (−5 650) |
| Накладные | 225 900 (+400) | 225 100 (−400) |
| Ставки для клиента | 225 500 (0) — фикс: ставки не влияют на NNE | 225 500 (0) |

Часы: `±(52 500 + 4 000) × 0,1 = ±5 650`. Утилизация +10%:
`C = 56 500 / 1,1 = 51 363,64`. Сумм в другой валюте в проекте нет, фактора
«курс» нет.

### 17.3. Пример 1, почасовая модель, УСН 6% + НДС 5%, X = 10%

| Фактор | −10%: NNE (Δ) | +10%: NNE (Δ) |
|---|---|---|
| Ставки для клиента | 49 400 (−9 400) | 68 200 (+9 400) |
| Часы | 52 740 (−6 060) | 64 860 (+6 060) |
| Утилизация | 55 088,89 (−3 711,11) | 61 836,36 (+3 036,36) |
| Накладные | 59 040 (+240) | 58 560 (−240) |

Ставки: выручка ±10 000, налог ±600. Часы: выручка ±10 000, издержки
`±(31 000 + 2 400) × 0,1 = ±3 340`, налог ±600. В почасовой модели часы —
источник выручки, в фиксе — риск: знак влияния часов противоположный.

Тот же проект с ценой «издержки + маржа» (пример 2, цена держится на 55 000):
часы +10% — NNE 13 160 (−3 340), −10% — 19 840 (+3 340); утилизация и
накладные — как в почасовой; ставки — 0. Если бы цена пересчитывалась, при
часах +10% она стала бы `38 540 / 0,64 = 60 218,75 ₽`.

### 17.4. «Что если»

- Все факторы применяются одновременно, их множители перемножаются. Ещё один
  фактор — **цена**: согласованная цена, потолок или удерживаемая цена
  «издержки + маржа» (в почасовой модели цену задают ставки).
- Проект не меняется. Значения «что если» живут в сессии, у каждого проекта
  свои, и в файл профиля не попадают.
- Для «издержки + маржа» дополнительно показывается пересчитанная цена — цена
  по закрытой формуле раздела 7.3 при изменённых издержках.

Пример. Слайд 3, часы +100% и утилизация −10%:
`NNE = 300 000 − 56 500 × 2 / 0,9 − 18 000 = 156 444,44 ₽` (маржа 52,15%).

## 18. План–факт

Код — `rentab_core.analysis.plan_fact`, модель факта — `ProjectActuals` и
`ActualHours` (`Project.actuals`), golden-тесты —
`tests/core/test_plan_fact.py`.

### 18.1. Факт

- Факт — часы по парам «этап × сотрудник»: `h^f_{s,i}`. План пары
  `h^p_{s,i}` — сумма назначений сотрудника `i` на этапе `s`.
- Пара плана без строки факта — 0 ч; интерфейс об этом предупреждает.
- Строка факта без плана — «вне плана» (`h^p = 0`): любой сотрудник команды на
  любом этапе проекта. Перерасход по ней — все её часы, процента нет.
- Исполнитель факта, которого нет в команде, в расчёт не входит, как и в
  плане (раздел 8.1).

### 18.2. Смета по факту

Тот же проект, в котором назначения заменены фактом; фирма, расходы, режим и
НДС — те же. Выручка по факту — по правилу выставления:

| Модель | Выставлено `R^f` |
|---|---|
| Почасовая | `V^f = Σ b·h^f` — выставляется факт |
| С потолком | `min(V^f, cap)` |
| Согласованная фикс-цена | `price` |
| Фикс «издержки + маржа» | `R^p` — цена плана держится |
| Вручную (любая модель) | `B` — фактически выставленная сумма, в режиме НДС проекта |

Дальше `C^f`, `Tax^f`, `NNE^f`, `m^f` и этапы — по разделам 3–8.

### 18.3. Реализация, списание, премия

```
realization = R / V        V — теневая стоимость без НДС (раздел 8.2)
списание    = max(V − R, 0)
премия      = max(R − V, 0)
```

Считаются по плану и по факту. Realization выше 100% значит, что фиксированная
цена дороже часов по ставкам («премия к ставкам»); она показывается как есть,
отрицательного списания не бывает. Если ставки для клиента не заданы
(`V = 0`), реализация не определена и показывается как «—».

### 18.4. Перерасход

```
пара:          Δh = h^f − h^p,   Δ% = Δh / h^p
исполнитель:   Δcost_i = (c_i + ρ)·Δh_i,   Σ_i Δcost_i = ΔLabor + ρ·ΔH = ΔC
роль:          сумма по сотрудникам роли
этап:          ΔH_s,   ΔC_s = ΔLabor_s + ρ·ΔH_s,   маржа и цвет этапа: план → факт
проект:        ΔNNE = ΔR − ΔC − ΔTax
```

Собственные расходы не меняются, поэтому весь `ΔC` — это часы. Перерасход
этапа считается без собственных расходов: их распределение по этапам
меняется вместе с теневой стоимостью.

### 18.5. Слайд 3: один проект «план → факт»

| | План | Факт | Отклонение |
|---|---|---|---|
| Часы П / Ю / С | 5 / 15 / 20 = 40 | 62 / 15 / 10 = 87 | +47 |
| Теневая стоимость `V` | 165 000 | 715 000 | +550 000 |
| Выставлено `R` | 300 000 | 300 000 | 0 |
| Реализация | 181,82% | 41,96% | −139,86 п. п. |
| Премия / списание | премия 135 000 | списание 415 000 | |
| Трудозатраты | 52 500 | 275 500 | +223 000 |
| Накладные | 4 000 | 8 700 | +4 700 |
| УСН 6% | 18 000 | 18 000 | 0 |
| **NNE** | **225 500** | **−2 200** | −227 700 |
| Маржа | 75,17% 🟢 | −0,73% 🔴 | −75,90 п. п. |
| К оплате | 315 000 | 315 000 | 0 |

| Роль | План, ч | Факт, ч | Δ ч | `c + ρ`, ₽/ч | Δ издержек |
|---|---|---|---|---|---|
| Партнёр | 5 | 62 | +57 | 4 100 | +233 700 |
| Юрист | 15 | 15 | 0 | 1 600 | 0 |
| Стажёр | 20 | 10 | −10 | 600 | −6 000 |
| Итого | 40 | 87 | +47 | | +227 700 |

`ΔNNE = 0 − 227 700 − 0 = −227 700`. По плану фиксированная цена на 82% выше
часов по ставкам, по факту клиент оплатил 42% отработанного.

| Этап | Исполнитель | План, ч | Факт, ч | Δ |
|---|---|---|---|---|
| 1. Анализ охраноспособности | Партнёр | 2 | 3 | +1 |
| 1. Анализ охраноспособности | Юрист | 8 | 10 | +2 |

| 2. Подготовка и подача заявки | Партнёр | — | 1 | +1, вне плана |
| Итого | | 24 | 30 | +6 |

По факту `Labor = 3·4 000 + 14·1 500 + 12·500 + 1·4 000 = 43 000`, накладные
`100 × 30 = 3 000`, `Own = 1 800`, `C^f = 47 800` (+12 600),
`V^f = 134 000`. Три модели цены, УСН 6% + НДС 5%:

| | Почасовая | С потолком 90 000 | «Издержки + маржа» (55 000) |
|---|---|---|---|
| `R`: план → факт | 100 000 → 134 000 | 90 000 → 90 000 | 55 000 → 55 000 |
| Реализация | 100% → 100% | 90,00% → 67,16% | 55,00% → 41,04% |
| Списание по факту | 0 | 44 000 | 79 000 |

Перерасход по исполнителям: партнёр +2 ч, из них 1 вне плана (+8 200 ₽),

почти не меняется. С потолком и в фиксе перерасход — за счёт фирмы.

**Выставлено вручную.** Если в почасовой модели фирма выставила не 134 000, а
120 000 ₽ (уступка клиенту): реализация 89,55%, списание 14 000, налог 7 200,
`NNE = 120 000 − 47 800 − 7 200 = 65 000 ₽`.

### 18.7. Ограничения

- Факт считается окончательным: освоение незавершённого проекта не
  моделируется.
- Факт — только часы и выставленная сумма. Ставки, себестоимость, накладные,
  курсы и расходы проекта — как в плане.

## 19. Сравнение моделей цены и налоговых режимов

Код — `rentab_core.analysis.compare`, тесты — `tests/core/test_compare.py`.

### 19.1. Матрица

Строки — налоговые режимы, столбцы — модели цены. Ячейка — смета проекта
(разделы 3–8) с этим режимом и этой моделью: выручка без НДС `R`, цена с НДС
`R + VAT`, к оплате, NNE, маржа.

| Столбец | Модель |
|---|---|
| Почасовая | `R = V` |
| С потолком | потолок проекта; если в проекте его нет — потолок, введённый на экране сравнения (не введён — «задайте потолок») |
| «Издержки + маржа» | раздел 7.3 при целевой марже проекта; если цель недостижима, в ячейке — причина |
| Согласованная цена | только если она задана в проекте |

| Страна | Режим | Варианты |
|---|---|---|
| РФ | УСН «доходы», УСН «доходы − расходы» | без НДС, НДС 5%, 7% |
| РФ | АУСН | — |
| РФ | НПД | 6% (юрлица), 4% (физлица) |
| РФ | ОСНО | НДС 22% |
| РК | ОУР ТОО, ОУР ИП | без НДС, НДС 16% |

- По умолчанию одна строка на режим: вариант, выбранный у фирмы, если режим
  текущий; иначе первый вариант без блокирующих замечаний валидатора (в порядке
  таблицы); если все варианты недоступны — вариант с наименьшим числом
  блокирующих замечаний. «Все варианты» — по строке на каждый.
- Тариф взносов: УСН и ОСНО — тариф фирмы (общий, МСП или нулевой), АУСН —
  0%, НПД — работников нет.
- Строки — только стран юрисдикции фирмы.
- Режим НДС проекта учитывается: при ценах «включая НДС» варианты НДС
  различаются и по NNE (`R = P / (1 + v)`), при ценах без НДС — только суммой
  «к оплате».

### 19.2. Доступность

Доступность — `check_profile(режим, FirmFacts, численность в стране)`
(раздел 15). Если есть блокирующее замечание, строка помечается
«недоступен» с текстом причин; цифры считаются и показываются приглушённо:
валидатор расчёт не останавливает. Предупреждения и сведения валидатора —
пометки.

### 19.3. Взносы сотрудников с окладом

Ставка взносов в карточке сотрудника рассчитана для текущего режима (раздел
3.1.1). В строке другого режима она пересчитывается по его правилам (АУСН —
0%, РК — СО, ООСМС, ОПВР и соцналог по форме), если совпадает с расчётной для
текущего режима с точностью до 0,01 п. п.: значит, её не меняли вручную.
Ставка, заданная вручную, остаётся. Поэтому строка текущего режима всегда
совпадает со сметой проекта.

### 19.4. Режим «Оба»

Две группы строк: РФ (смета в ₽) и РК (в ₸). Проект считается так, как если
бы его вели в стране строки: она становится страной расчёта налога. У группы,
валюта которой не совпадает с валютой проекта, NNE дополнительно пересчитан в
валюту проекта по курсу фирмы — для сравнения.

### 19.5. Пример 1 у демо-фирмы

Демо-фирма: ООО, доход за год 24 млн ₽, три сотрудника, стоимость задана
суммой в месяц. Потолок 90 000 ₽, `m* = 30%`, пошлина 15 000 ₽.

| Режим | Доступность | Почасовая: NNE / к оплате | С потолком 90 000 | «Издержки + маржа» 30% |
|---|---|---|---|---|
| ▶ УСН «доходы» 6% + НДС 5% | ✅ | 58 800 / 120 000 | 49 400 / 109 500 | 16 500 / 72 750 |
| УСН «доходы − расходы» 15% + НДС 5% | ✅ | 55 080 / 120 000 | 46 580 / 109 500 | 16 320 / 72 120 |
| АУСН 8% | ℹ️ проверить, участвует ли регион | 56 800 / 115 000 | 47 600 / 105 000 | 17 032,26 / 71 774,19 |
| НПД 6% (юрлица) | ⛔ организация; есть работники; доход больше 2,4 млн ₽ | (58 800 / 115 000) | (49 400 / 105 000) | (16 500 / 70 000) |
| ОСНО 25% + НДС 22% | ✅ | 48 600 / 137 000 | 41 100 / 124 800 | 17 600 / 86 573,33 |

- Варианты УСН без НДС недоступны (доход больше 20 млн ₽) — их видно в режиме
  «все варианты».
- НДС не меняет NNE, меняет только сумму «к оплате».
- В «издержки + маржа» `NNE = m*·P`: режим с высоким налогом даёт более высокую
  цену для клиента, а не меньшую прибыль (у ОСНО `P = 58 666,67 ₽`, к оплате
  86 573,33 ₽). Здесь режимы сравнивают по сумме «к оплате».

Слайд 3, столбец «согласованная цена 300 000 ₽»: УСН 6% — 225 500, УСН 15% —
206 975, АУСН — 219 500, ОСНО — 182 625 (к оплате 366 000 ₽).
